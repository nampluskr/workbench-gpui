## 확신 낮은 부분

1. **우리 앱의 Zed 공식 레지스트리(`api.zed.dev` / `zed-industries/extensions`) 직접 사용 가능 여부 (`X-52`, 판단 필요)**:
   - 기술적으로 Zed 클라이언트가 호출하는 엔드포인트(`GET https://api.zed.dev/extensions`, `/extensions/{id}/{version}/download` 등)는 인증 토큰 없이 공개 `.tar.gz` 패키지를 반환하지만, `api.zed.dev`는 Zed Industries의 자체 인프라 서비스이므로 제3자 에디터가 프로덕션에서 직접 호출하는 것이 서비스 약관·정책상 허용되는지는 코드만으로 확정할 수 없다(**판단 필요**).
   - 반면 `https://github.com/zed-industries/extensions` 저장소에 등록된 개별 확장 저장소들은 오픈소스 라이선스(`MIT`, `Apache-2.0` 등, `X-62`)를 따르므로, Git 서브모듈 목록을 기반으로 자체 정적 인덱스/릴리스 버킷을 운영하거나 로컬/URL 설치를 지원하는 방향은 법적·기술적 제약이 없다.
2. **언어 확장 패키지의 불필요한 `extension.wasm` 처리 방식 (`X-21`, `X-29`)**:
   - Zed 공식 레지스트리의 다수 언어 확장(예: 로컬 `installed/html`)은 하나의 확장 패키지 안에 `languages/` + `grammars/*.wasm`(구문 강조)과 `[language_servers.*]` + `extension.wasm`(LSP 구동 코드)을 함께 묶어 배포한다.
   - 우리 앱은 LSP를 제외하고 언어/구문 강조만 지원하므로, 기존 Zed 언어 확장 패키지를 그대로 설치할 때 매니페스트의 `lib` / `language_servers` 필드를 파싱 에러 없이 무시하고 `extension.wasm`을 로드하지 않더라도 `languages/*`와 `grammars/*.wasm`만으로 정상 작동한다(실제로 `extension_host.rs`에서 문법·언어 등록은 `WasmExtension::load`와 완전히 독립된 단계로 수행됨을 코드로 확인함).

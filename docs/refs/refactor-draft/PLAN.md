Phase별 목표, 작업 범위, 담당, 검증, 완료 기준을 정의한다. 에이전트 구성과 운영 규칙은 HERDR.md, 공통 지침과 검증 수준(V0~V4)은 AGENTS.md를 따른다.

- 기준일: 2026-11-02
- 소유자: 사용자 (수정은 사용자 승인 후 `lead`가 반영)

## 2. 공통 운영 규칙

### 2.1 Phase 진행

- Phase는 순서대로 진행한다. 이전 Phase의 완료 기준을 통과해야 다음 Phase를 시작한다.
- 같은 Phase 안에서 `impl-editor`와 `impl-ui`는 서로 다른 범위를 병렬로 진행할 수 있다.
- P2~P5는 리팩토링 Phase다. 동작을 변경하지 않으며, 동작 변경이 필요하면 P6 작업 카드로 분리한다.
- Phase 진행 중 계획 변경이 필요하면 `lead`가 사용자에게 보고하고 승인 후 이 문서를 수정한다.

### 2.2 Phase 시작 시 (`lead`)

1. 이 문서의 해당 Phase 절을 기준으로 작업 카드를 `docs/agents/TASKS.md`에 작성한다.
2. 작업 카드마다 검증 수준(V0~V3)을 지정한다. 기본값은 V0이다.
3. 작업 카드 목록을 사용자에게 보고하고 승인 후 지시를 시작한다.

### 2.3 Phase 종료 시 (`lead`)

1. 해당 Phase에서 변경된 화면과 누적된 "실측 필요" 항목을 묶어 V3 작업 카드를 만든다.
2. V3 결과 불일치는 rework 카드로 처리하고, 불일치 항목만 재측정한다.
3. "사용자 확인 필요" 항목을 모아 사용자에게 한 번에 전달한다(V4).
4. `/ponytail-debt`로 의도적 단순화 목록을 점검한다.
5. `docs/agents/HANDOFF.md`를 갱신하고 git 태그(`phase-<번호>`)를 남긴다.
6. 완료 기준 충족 여부를 사용자에게 보고하고, 승인 후 다음 Phase로 넘어간다.

## 3. Phase 상세

### P0 기준선

**목표:** 리팩토링 전 상태를 고정하여 이후 모든 Phase의 회귀 비교 기준으로 삼는다.

**시작 조건:** HERDR.md 3장 초기 설정 완료, 에이전트 5개 실행 및 역할 이름 지정 완료

| 카드 | 담당 | 내용 | 검증 |
|---|---|---|---|
| P0-1 | reviewer | main 기준선 `cargo build`, `cargo test`, `cargo clippy` 결과 기록 | V0 |
| P0-2 | reviewer | `@ponytail-audit` 전체 실행, 결과 분류(하드코딩 수치/색상, 반복 스타일 체인, 중복 컴포넌트, 미사용 의존성, 기타) | - |
| P0-3 | spec | Zed 실측 결과를 `spec/zed-metrics.toml`로 변환(ID, 값, 단위, 출처, 측정 조건) | - |
| P0-4 | impl-editor, impl-ui | 각 worktree 빌드 확인, 담당 범위 모듈 구조 요약(코드 수정 없음) | V0 |
| P0-5 | lead | `<EDITOR_CORE_PATHS>`, `<UI_SHELL_PATHS>` 후보 제안, 사용자 확정 | - |
| P0-6 | reviewer | 현재 화면 전체 V3 기준 실측(리팩토링 전 측정값 보존) | V3 |

**산출물**
- `docs/agents/reviews/baseline-<date>.md`
- `docs/agents/reviews/audit-<date>.md`
- `spec/zed-metrics.toml`, 모호 항목 목록
- `docs/agents/reviews/measure-p0.md`

**완료 기준**
- 위 산출물이 모두 존재한다.
- HERDR.md 4장의 경로 자리표시자가 실제 경로로 확정됐다.
- P0 동안 src 변경이 없다.

**주의**
- 기존 코드에 clippy 경고가 많으면 P0에서는 `-D warnings` 없이 기준선을 기록하고, 경고 정리는 P2 이후 카드로 분리한다.
- P0-6의 불일치는 고치지 않는다. 이후 Phase의 rework 대상 목록으로만 남긴다.

### P1 검증 기반

**목표:** V2 레이아웃 테스트와 V3 실측을 빠르게 수행할 수 있는 도구를 먼저 갖춰, 이후 Phase의 검증 시간을 줄인다.

**시작 조건:** P0 완료, `spec/zed-metrics.toml` 존재

| 카드 | 담당 | 내용 | 검증 |
|---|---|---|---|
| P1-1 | reviewer | 레이아웃 테스트 요구사항 작성(스펙 ID 조회 방식, 허용 오차, 실패 메시지 형식) | - |
| P1-2 | impl-editor | 테스트에서 스펙 ID로 기대값을 조회하는 헬퍼 구현 | V1 |
| P1-3 | impl-editor | 대표 레이아웃 테스트 1~2개 작성(P0-6 측정 항목 중 반복 빈도가 높은 것) | V2 |
| P1-4 | impl-editor | 레이아웃 덤프 기능: 환경 변수로 켜면 지정 요소의 bounds를 JSON으로 출력 | V1 |
| P1-5 | reviewer | V3 측정 스크립트(스크린샷 기반 픽셀 측정, 덤프 JSON과 스펙 비교) | - |

**산출물**
- 스펙 조회 헬퍼와 레이아웃 테스트 예시
- 레이아웃 덤프 기능과 사용법
- `tools/measure/` 측정 스크립트와 사용법

**완료 기준**
- 새 레이아웃 테스트를 스펙 ID만 지정해서 작성할 수 있다.
- V3 실측을 덤프 JSON 또는 측정 스크립트로 수행할 수 있다.

**주의**
- 스펙 파일 파싱에 새 크레이트가 필요하면 기존 의존성부터 확인하고, 추가가 필요하면 사용자 승인을 받는다.
- 측정 스크립트는 Python으로 작성하고 경로는 `os.path`를 사용한다. 주석은 영어로 작성한다.
- 공통 모듈과 `tools/measure/`의 소유자는 `lead`가 카드 단위로 지정한다.

### P2 상수/테마 통합

**목표:** 코드에 흩어진 수치와 색상을 스펙과 테마 모듈로 옮겨, 이후 모든 수정이 한 곳에서 이루어지게 한다.

**시작 조건:** P1 완료

**작업 범위**
- P0 감사 결과의 "하드코딩 수치/색상" 항목 전체
- 수치는 스펙 ID 기반 상수 모듈로, 색상은 테마 모듈로 이전
- 같은 값이라도 스펙 ID가 다르면 별개 상수로 유지

**담당:** 공통 모듈은 `lead`가 지정, UI 셸 쪽은 `impl-ui`, 에디터 쪽은 `impl-editor`

**검증**
- 같은 값의 치환은 V0
- 값이 바뀌는 치환(기존 값과 스펙 값이 다른 경우)은 V2

**완료 기준**
- 하드코딩 수치/색상 0건(reviewer가 감사로 확인)
- 변경 화면 V3 실측 통과

---

### P3 공통 컴포넌트

**목표:** 반복되는 스타일 체인과 유사 컴포넌트를 통합하여 중복을 제거한다.

**시작 조건:** P2 완료

**작업 범위**
- P0 감사 결과의 "반복 스타일 체인", "중복 컴포넌트" 항목
- gpui kit에 같은 기능의 컴포넌트가 있으면 우선 검토, 크기나 동작이 실측과 다르면 자체 구현 유지
- 사용하지 않는 의존성 제거

**담당:** `impl-ui` (에디터 쪽 중복은 `impl-editor`)

**검증**
- 컴포넌트 교체 후 동일 props는 V0
- 렌더 결과가 달라질 수 있는 통합은 V2

**완료 기준**
- 감사 기준 중복 컴포넌트 0건
- 변경 화면 V3 실측 통과

---

### P4 UI 셸 정리

**목표:** 메뉴, 아이콘, 패널, 타이틀바, 상태바를 Zed 실측과 일치시킨다.

**시작 조건:** P3 완료

**작업 범위**
- P0-6 기준 실측의 UI 셸 불일치 항목
- 화면 영역별(titlebar, menu, panel, statusbar, icon)로 카드 분할

**담당:** `impl-ui`

**검증**
- 크기와 배치 수정은 V2
- 레이아웃 테스트로 잡을 수 없는 항목(아이콘 래스터 크기, 실제 텍스트 폭)은 "실측 필요"로 보고

**완료 기준**
- UI 셸 영역 V3 실측 통과
- 반복 측정 항목은 V2 테스트로 이전 완료

### P5 에디터 코어 정리

**목표:** 텍스트 버퍼, 커서, 선택, 텍스트 레이아웃, IME, 스크롤을 Zed 동작 및 실측과 일치시킨다.

**시작 조건:** P3 완료 (P4와 병렬 진행 가능)

**작업 범위**
- P0-6 기준 실측의 에디터 영역 불일치 항목
- 로직 단위(커서 이동, 선택 확장, 줄바꿈, 스크롤)로 카드 분할

**담당:** `impl-editor`

**검증**
- 로직은 V1, 상호작용은 `#[gpui::test]` 입력 시뮬레이션으로 검증
- 줄 높이, 거터, 커서 크기 등 배치는 V2
- IME 조합 위치처럼 테스트로 잡기 어려운 항목은 "실측 필요"로 보고

**완료 기준**
- 에디터 코어 V1 테스트 통과
- 에디터 영역 V3 실측 통과

### P6 신규 기능

**목표:** 정리된 기반 위에서 기능을 확장한다.

**시작 조건:** P4, P5 완료

- 새 수치는 먼저 `spec`이 스펙에 추가한 뒤 구현한다.

**완료 기준**
- 카드별 완료 기준 통과
- 마일스톤마다 변경 화면 V3 실측 통과

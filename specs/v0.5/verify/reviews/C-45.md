## 2. 동시성 및 정확성 리뷰 (Code Reading)

### 2.1 백그라운드 전송 값의 `Send` 보장 및 UI 상태 비차용
- `run_full_parse`에서 백그라운드 태스크로 전송되는 데이터는 `FullParse` 구조체임:
  ```rust
  struct FullParse {
      resources: &'static QueryResources,
      id: &'static str,
      text: Rope,
      generation: u64,
  }
  ```
  - `resources`: `&'static QueryResources` (`Sync + Send + 'static`)
  - `id`: `&'static str` (`Sync + Send + 'static`)
  - `text`: `gpui_kit::Rope` (불변 영속 텍스트 복사본, `Send + 'static`)
  - `generation`: `u64` (`Send + 'static`)
- 백그라운드 클로저(`async move { job.run() }`) 내부에서 `Parser`를 새로 생성하여 독립적으로 파싱을 수행하며, `Window`, `EditorState`, `cx` 등 UI 스레드 상태를 일체 참조하거나 빌리지 않음.

### 2.2 세대 번호(Generation)를 통한 지연/재시작 결과 폐기
- `ParseState`의 `generation` 카운터:
  - 파일 전체 교체나 새 파싱 시작 시 `start_full`에서 `generation += 1` 증가.
  - `finish(done)`에서 `self.parse.flight`의 `generation`과 `done.generation`을 대조.
  - 일치하지 않는 경우(예: 파싱 도중 사용자가 `set_value`나 언어 변경으로 재시작한 경우) `finish`는 `false`를 반환하고 수신한 결과를 아무런 상태 변경 없이 안전하게 폐기함.
  - 비행 중인 파싱이 없을 때(`flight == None`) 도착한 지연 결과 역시 즉시 무시됨.

### 2.3 파싱 중 편집 로그 순서 및 오프셋 재생
- 백그라운드 파싱이 진행되는 도중 들어오는 편집(`changed` 호출)은 `flight.log`에 `InputEdit` 형태로 순서대로 누적(`log.extend(...)`)되고 최신 `text`만 갱신됨.
- `finish`에서 파싱 결과가 설치될 때:
  ```rust
  if self.root.is_some() && !log.is_empty() {
      for edit in &log { self.edit(edit); }
      let text = self.text.clone();
      self.reparse(&text);
  }
  ```
  - 누적된 편집을 발생 순서대로 트리에 `edit`하여 오프셋 델타를 선형 누적 반영함.
  - 마지막에 최신 텍스트로 단 1회의 증분 `reparse`를 수행하므로, 파싱 도중 타이핑이 발생해도 결과가 버려지지 않고 정확한 증분 상태로 복구됨 (`edits_during_the_first_parse_are_replayed_and_restarts_discard_the_result` 테스트로 검증됨).

### 2.4 하이라이터 폐기 시 `Weak`/`Task` 수명 및 누수 방지
- 비동기 대기 경로(`run_full_parse`의 `Err(rest)`):
  ```rust
  let weak = Rc::downgrade(shared);
  let task = cx.spawn(async move |editor, cx| {
      let done = rest.await;
      let Some(shared) = weak.upgrade() else { return };
      let applied = shared.borrow_mut().finish(done);
      if applied { editor.update(cx, |editor, cx| editor.refresh(cx)).ok(); }
  });
  shared.borrow_mut().parse.task = Some(task);
  ```
  - 포그라운드 작업(`task`)은 `SharedHighlighter`를 `Weak`로만 참조함.
  - 하이라이터가 `Task`를 소유하므로, 탭이 닫히거나 새 하이라이터로 교체될 때 `Task`가 drop되어 대기 작업이 안전하게 취소됨.
  - 참조 순환이 없어 메모리 누수가 발생하지 않음.

### 2.5 `RefCell` `borrow_mut` 충돌 가능성 분석
- `shared.borrow_mut()` 호출 지점:
  1. `SharedHighlighter::update` / `update_batch` (에디터 이벤트 핸들러 내 동기 호출)
  2. `highlighter_factory` 생성 시
  3. `run_full_parse`:
     - 1ms 타임아웃 내 완료 시 동기 분기 (`Ok(done)`)
     - 비동기 분기 (`task` 내부 `rest.await` 이후): UI 이벤트 루프의 별도 틱에서 실행되므로 렌더링 중 발생하는 `styles()` (`borrow()`)와 겹치지 않음.
  4. `editor.refresh(cx)`는 에디터 다시 그리기를 비동기 큐에 예약하므로, `borrow_mut` 스코프가 완전히 종료된 이후에 후속 렌더가 일어남.
  - `borrow_mut` 패닉 가능성 없음.

### 2.6 `block_with_timeout` 1ms 경로의 중복 반영 방지
- `block_with_timeout(SYNC_PARSE_TIMEOUT, work)`가 `Ok(done)`을 반환하면 `shared.borrow_mut().finish(done)`만 수행되고 `Err` 분기는 실행되지 않음.
- `Err(rest)` 분기로 넘어간 경우에만 `rest.await`를 기다리는 `task`가 생성되므로, 동일한 파싱 결과가 두 번 반영되는 경로는 구조적으로 존재하지 않음.

### 2.7 트리가 없는 상태(백그라운드 파싱 중)의 안정성
- `runs`: `self.root.is_none()`일 때 `vec![(range.clone(), HighlightStyle::default())]`(평문)를 반환하여 패닉 없이 안전하게 렌더링됨.
- `symbols`: `self.root.is_none()`일 때 빈 `Vec`을 반환하여 경로 줄에 파일명만 노출됨.
- `fold_ranges`: 빈 `Vec` 반환.
- 모든 조회 메서드가 `None` 트리에 대해 안전하게 방어되어 있음.

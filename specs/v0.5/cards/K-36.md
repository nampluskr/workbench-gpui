# K-36 — 탭이 넘칠 때 끝 빈 자리(드롭 자리)를 스크롤 안으로
V3 4차(`specs/v0.5/verify/reviews/measure-ORDER-09-run4/app-step3-first-active.png`): 탭이 넘쳐도 마지막 탭과 오른쪽 버튼 묶음 사이에 약 24px 빈 자리가 늘 남는다. Zed(`D:\projects\workbench-tauri\specs\v0.5\verify\ORDER-09\zed-overflow.png`)는 탭이 버튼 묶음 바로 앞에서 잘린다.
Zed 근거(`%TEMP%\zed-src-4304dec7`, 읽기만·복사 금지): `crates/workspace/src/pane.rs:3721-3728` — 끝 드롭 자리(`render_tab_bar_drop_target`, 3731~, `min_w_6`·`flex_grow`)가 `overflow_x_scroll()` 탭 컨테이너의 **마지막 자식**이다. 그래서 넘칠 때는 탭과 함께 스크롤되어 밖으로 나가고, 넘치지 않을 때는 남은 폭을 채운다. 핀 탭 쪽(3694~3697)도 같은 구조인지 보고(이 앱에 핀 탭 줄이 따로 없으면 해당 없음으로).
1. K-33에서 만든 스크롤 행(`layout.rs` `tab_list`, `tab-scroll`) 안 끝에 드롭 자리를 옮긴다. 드롭 동작(`end_drop`·드롭 표시 색)과 probe 이름(`tab-bar-filler`)은 그대로. 최소 폭은 지금 상수 그대로(24, 기존 toml ID `tab.overflow.empty_drop_width` 등 지금 쓰는 것).
2. 넘치지 않을 때 모양(남은 폭을 채움)은 지금과 같아야 한다. 활성 탭 보이기(`scroll_to_item`)는 탭 인덱스 기준이라 마지막 자식이 하나 늘어도 맞는지 확인.
3. 테스트: 가능하면 레이아웃 계산 테스트, 아니면 코드 확인과 보고의 "실측 필요".

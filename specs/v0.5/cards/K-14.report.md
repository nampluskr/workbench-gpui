## 구현

- v 메뉴 Keymap·Ctrl-K Ctrl-S로 Keymap Editor를 연다. 다른 workspace까지 기존 탭을 검색해 있으면 해당 workspace·pane·탭을 활성화한다. 폴더가 없어도 설정 workspace에서 연다.
- 도구 탭 내용·포커스를 기존 Tab에 담는다. 도구는 Docs에 등록하지 않아 저장·감시 대상 파일이 되지 않는다. 탭 이동·복제에서 도구 내용을 보존하고, 닫기는 수정 없는 탭으로 처리한다.
- 위 필터 `Filter action names…`, `Edit in JSON`(Ctrl-E), `Create Keybinding`(Ctrl-K), 열 Action / Arguments / Keystrokes / Context / Source를 표시한다. 실행 중인 키맵의 gpui-kit·앱 기본·사용자 바인딩과 바인딩 없는 앱 액션을 표시한다. Source는 Default/User다. 인자 없는 앱 액션의 Arguments는 비워 둔다.
- 행 클릭으로 편집, Create로 새 바인딩 입력 후 Save/Cancel. 액션·키·컨텍스트는 저장 전에 gpui 파서로 검증한다. UI 기본 액션도 사용자 파일에서 사용할 수 있도록 기존 사용자 키맵 읽기는 등록된 액션을 함께 확인한다.
- 저장 시 이전 키/컨텍스트가 달라졌으면 이전 키를 null로 해제하고 새 바인딩을 마지막 override 섹션에 추가한다. 기존 주석·키·내용·BOM·후행 쉼표를 보존한다. 파일 형식은 기존 Zed JSONC 섹션 배열이며, 파일이 잘못됐으면 저장을 거부한다. 반복 편집 시 override가 늘어나는 한계를 shortcut 주석에 명시했다.
- 저장 후 기존 load로 즉시 적용하며 외부 JSON 편집·재시작 시에는 기존 파일 읽기와 감시 흐름이 적용한다. JSON 편집은 실제 사용자 keymap.json을 일반 편집기 탭으로 열고, 파일이 없으면 빈 배열로 생성한다. 오류는 화면에 표시한다.
- 필터·Source, 기존 키 해제, 빈 배열·주석·BOM·후행 쉼표, 잘못된 JSON 거부, 임시 파일 실제 저장·기존 파서 재읽기를 테스트했다. 실사용 앱 데이터는 테스트에서 건드리지 않았다.

## 범위·후속 확인

키 입력 검색·필터 버튼은 ORDER-06-R1 2.2의 선택 사항으로 생략했다. 키는 gpui 표기(예: `ctrl-alt-k`)를 입력한다. 행 편집은 표 아래 입력 영역을 사용한다. Zed와 같은 모달 편집·녹화 방식까지는 구현하지 않았으므로 writer가 두 갈래 차이로 기록하고 leader가 후속 범위를 판정해야 한다.

생략·위험: 앱·UI 실측과 gpui 입력 시뮬레이션은 미수행이다. 화면 일치·상호작용 PASS는 선언하지 않으며 V3와 입력 검증이 남아 있다. 반복 편집 시 사용자 파일에 override 섹션이 누적된다.

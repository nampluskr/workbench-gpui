## 누락 시 동작과 남은 출처

- 시작 시 `menu.svg`가 없으면 stderr에 `zed icons missing: run tools/fetch-zed-icons.ps1`를 한 번 출력한다.
- 누락된 Zed SVG는 AssetSource가 `Ok(None)`을 반환한다. gpui SVG 요소의 크기는 기존 `.size(...)`로 유지되므로 같은 크기의 빈 아이콘 자리가 남는다. 아이콘을 직접 그리거나 대체 그림을 만들지 않는다.
- `missing_zed_icons_are_empty_without_panic`은 존재하지 않는 폴더에서 load·list가 빈 결과를 반환하고 패닉이 없음을 확인한다. 경로 이탈 요청 차단과 gpui-kit 기본 아이콘 자산 공존도 같은 테스트에서 확인했다.
- 남은 비-Zed 출처는 `src/ui/panel_view.rs`의 `IconName::File` 하나다. 카드가 이번에는 파일 트리 파일 아이콘을 유지하도록 명시했기 때문에 남겼다(Phase 7).
- 남은 비-SVG 출처: 창 제어 버튼 4개의 Segoe Fluent Icons(없으면 Segoe MDL2 Assets) 글리프. Zed도 Windows에서 같은 글리프를 쓴다(K-08-R1의 leader 확인). Linux용 `generic_*.svg`는 창 제어에 사용하지 않는다.
- gpui-kit 내부 컴포넌트용 기본 자산도 계속 제공한다. 앱 자체의 다른 `IconName`은 위 파일 아이콘 외에는 제거했다. 글리프·글꼴 선택은 창 제어에만 사용하고 탭 고정 아이콘은 Zed SVG를 유지한다.
- V1 범위에 따라 앱 실행·화면 조작·전체 테스트는 생략했다. V3 완료로 주장하지 않는다. 폴더 UI SVG 대응은 위 표의 애매 항목으로 남는다.

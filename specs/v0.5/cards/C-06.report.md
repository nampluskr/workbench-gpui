## 1. 항목별 검토 결과

### (1) 원인 확인: coder의 소스 분석 타당성 (충족)
`gpui-pre-windows-0.3.10` 소스 확인 결과, coder의 원인 분석은 정확하다.
1. `src/events.rs` (`handle_calc_client_size`):
   - `hide_title_bar` 창의 `WM_NCCALCSIZE` 처리 시 `DefWindowProcW` 호출 후 `(*params).rgrc[0].top = saved_top;`으로 상단 경계를 복원한다.
   - 따라서 상단 비클라이언트 테두리는 0px이며, 좌/우/하단에만 DWM 리사이즈 테두리(`SM_C*FRAME + SM_CXPADDEDBORDER`)가 남는다.
2. `src/window.rs` (`WindowBorderOffset::update`):
   - `height_offset`을 `(window.bottom - window.top) - (client.bottom - client.top)`으로 측정하므로, 하단 테두리 두께만 단독으로 기록된다(100% 기준 8px).
3. `src/window.rs` (`calculate_window_rect`):
   - 창 사각형을 계산할 때 `top_offset = height_offset / 2`, `bottom_offset = height_offset - top_offset`으로 비대칭성을 고려하지 않고 상하로 균등 배분(-4px, +4px)한다.
4. 결과:
   - `retrieve_window_placement`에서 `initial_bounds` 상단을 4px 위로 올린 위치를 OS 창의 상단으로 지정하고, `handle_calc_client_size`에 의해 클라이언트 상단이 그대로 창 상단에 맞춰지므로 보이는 클라이언트 영역 전체가 작업 영역 중심보다 위로 4px 치우치게 된다.

### (2) 정확성: 보정량 및 DPI 계산 (충족)
1. **보정량 계산**:
   - `SM_CYSIZEFRAME + SM_CXPADDEDBORDER`는 gpui 내부 `events.rs`의 `get_frame_thicknessy`와 완전히 동일한 정의다.
   - gpui의 `calculate_window_rect`가 수행하는 상단 배분 오프셋 `height_offset / 2`는 Rust `i32` 정수 나눗셈(절삭)이다.
   - coder의 구현 `(frame_height / 2) as f32 / scale` 역시 동일하게 `frame_height / 2` 정수 나눗셈을 수행한 뒤 논리 픽셀로 변환한다.
   - gpui가 `to_device_pixels(scale)`로 물리 좌표 변환 시 `((frame_height / 2) / scale * scale).round() == frame_height / 2` 정수가 되므로, gpui의 `top_offset` 감산과 완전히 상쇄(`+k - k = 0`)된다.
2. **`GetDpiForSystem`과 주 모니터 DPI**:
   - 본 앱은 매니페스트(`perMonitorV2`)로 DPI를 인식하며, 시작 창은 `cx.primary_display()`(주 모니터)의 `visible_bounds()`를 기준으로 생성된다.
   - Windows에서 `GetDpiForSystem()`은 주 모니터의 시스템 DPI를 반환하므로 주 모니터 배율과 정확히 일치한다.
   - gpui 외부 공개 API(`PlatformDisplay`)로는 모니터의 DPI나 배율을 직접 조회할 수 없으므로, Win32 API 직접 호출은 불가피하고 적절하다.
3. **배율별 정량 검증 (100%, 125%, 150%, 200%)**:
   - **100% (96 DPI, 1.0x)**:
     - `SM_CYSIZEFRAME`=4, `SM_CXPADDEDBORDER`=4 → `frame_height`=8.
     - `frame_height / 2` = 4. 논리 보정량 = +4.0 px. gpui `top_offset` = 4 px. 오차 0.0 px.
   - **125% (120 DPI, 1.25x)**:
     - `SM_CYSIZEFRAME`=4, `SM_CXPADDEDBORDER`=5 → `frame_height`=9.
     - `frame_height / 2` = 4. 논리 보정량 = 4.0 / 1.25 = +3.2 px. gpui `top_offset` = 4 px.
     - 852 * 1.25 = 1065 physical px (홀수). 홀수 픽셀 배치에 따른 0.5px 외 오차 0.0 px (<= 1px 충족).
   - **150% (144 DPI, 1.5x)**:
     - `SM_CYSIZEFRAME`=5, `SM_CXPADDEDBORDER`=6 → `frame_height`=11.
     - `frame_height / 2` = 5. 논리 보정량 = 5.0 / 1.5 = +3.333... px. gpui `top_offset` = 5 px. 오차 0.0 px.
   - **200% (192 DPI, 2.0x)**:
     - `SM_CYSIZEFRAME`=5, `SM_CXPADDEDBORDER`=8 → `frame_height`=13.
     - `frame_height / 2` = 6. 논리 보정량 = 6.0 / 2.0 = +3.0 px. gpui `top_offset` = 6 px. 오차 0.0 px.
   - 결론: 모든 배율에서 계산 오차 0 px (홀수 크기 반올림 시 최대 0.5px 이하)로 ORDER-02-R1 허용 오차(1px 이하)를 만족한다.

## 2. 지적 사항 (개선 권고)

- **파일 및 위치**: `src/ui/mod.rs` (라인 806~821, `initial_window_uses_work_area_center_and_fixed_client_size`)
- **사유**: 더한 수식을 그대로 빼는 동어반복 검증 대신, 실제 Windows DWM 메트릭에 기반한 구체적 오프셋 기댓값(`expected_offset_y`)을 명시적으로 검증하는 것이 테스트의 독립성과 회귀 방지력을 높임.
- **기대 수정 (예시)**:
  ```rust
  #[test]
  fn initial_window_uses_work_area_center_and_fixed_client_size() {
      // 100% (frame_height 8, scale 1.0): offset = +4.0 px
      // 125% (frame_height 9, scale 1.25): offset = +3.2 px (4 / 1.25)
      // 200% (frame_height 13, scale 2.0): offset = +3.0 px (6 / 2.0)
      for (work_area, frame_height, scale, expected_offset_y) in [
          (Bounds::new(point(px(0.), px(0.)), size(px(1920.), px(1040.))), 8, 1., px(4.)),
          (Bounds::new(point(px(-1920.), px(40.)), size(px(1920.), px(1040.))), 9, 1.25, px(3.2)),
          (Bounds::new(point(px(40.), px(0.)), size(px(1240.), px(720.))), 13, 2., px(3.)),
      ] {
          let options = window_options(work_area, frame_height, scale);
          let Some(WindowBounds::Windowed(bounds)) = options.window_bounds else {
              panic!("expected a windowed startup");
          };
          assert_eq!(bounds.size, WINDOW_INITIAL_SIZE);
          assert_eq!(bounds.center().x, work_area.center().x);
          assert_eq!(bounds.center().y, work_area.center().y + expected_offset_y);
          assert_eq!(options.window_min_size, Some(WINDOW_MIN_SIZE));
          assert!(options.titlebar.unwrap().appears_transparent);
      }
  }
  ```

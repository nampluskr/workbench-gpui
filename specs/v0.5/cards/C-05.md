# C-05 — 시작 창 V3 실측 (R-6 = I-6)

AGENTS.md 3A.4 절차를 따른다. 측정 목록 밖은 재지 않는다. 기능 확인용 조작은 하지 않는다. 눈대중 판정 금지.

## 측정 목록 (ORDER-02 3장)
1. 첫 실행(앱 데이터 없음): 작업 영역(rcWork) left·top·width·height, 창 바깥 사각형(GetWindowRect), 클라이언트 크기(GetClientRect)와 화면 원점(ClientToScreen). 기대: 클라이언트 1440×852, 클라이언트(또는 창) 중심 = 작업 영역 중심(±1px). 둘 다 숫자로 적는다.
2. 최소 크기: 창을 `SetWindowPos`로 100×100까지 줄이라고 시킨 뒤 클라이언트 크기를 다시 읽는다. 기대: 360×240보다 작지 않다.
3. 다시 실행: 2 상태(또는 1600×900 등 다른 크기로 바꾼 상태)에서 앱을 정상 종료하고 다시 띄운 뒤 1과 같은 값을 잰다. 기대: 1440×852, 작업 영역 가운데.

## 방법
- 조건: 주 모니터 1920×1080, 배율 100%(바꾸지 않는다), 작업 표시줄 있음. 측정 중 사용자 입력 없음.
- 앱 데이터 백업·초기화·복원: `pwsh -NoProfile -File tools/measure/session.ps1 -Action Start -Out specs\v0.5\verify\reviews\measure-ORDER-02 -Exe D:\projects\workbench-gpui\target\debug\workbench-gpui.exe` … 끝에 `-Action Stop -Out ...`. (`-Out`은 반드시 v0.5 폴더. 기본값은 v0.3 폴더라 쓰지 않는다.) 3의 재실행은 `session.ps1` 없이 같은 exe를 직접 다시 띄워도 된다(데이터는 Stop 때 복원).
- 창 측정: Win32 `GetWindowRect`·`GetClientRect`·`ClientToScreen`·`SystemParametersInfo(SPI_GETWORKAREA)`·`SetWindowPos`를 부르는 작은 PowerShell 스크립트를 `tools/measure/window-rect.ps1`로 만든다(checker 소유 폴더). 결과는 `-Out` 폴더에 JSON/텍스트로.
- 승인 창이 뜨는 명령은 leader가 판단한다(5.6). 새 의존성·`src/` 수정 금지.
- 끝나면 앱이 모두 종료됐는지 확인한다(`Get-Process workbench-gpui`).

# K-02 — 시작 창: 클라이언트 영역을 작업 영역 정가운데로 (세로 −4px 고치기)

## 배경
K-01(`specs/v0.5/cards/K-01.md`, `K-01.report.md`, 커밋 a6fcf2e)로 클라이언트 1440×852는 맞다. 그런데 V3 실측(`specs/v0.5/verify/reviews/measure-ORDER-02.md`)에서 클라이언트 중심이 작업 영역 중심보다 **위로 4px**였다(배율 100%):
- 작업 영역 (0,0)–(1920,1032), 중심 (960,516)
- GetWindowRect (232,86)–(1688,946) 1456×860 → 창 중심 (960,516)
- 클라이언트 원점 (240,86) 1440×852 → 클라이언트 중심 (960,512)
- 원인: OS 타이틀 바를 숨긴 창이라 보이지 않는 테두리가 왼쪽·오른쪽·아래(각 8px)에만 있고 위는 0이다. gpui는 클라이언트 bounds에 비클라이언트 크기를 더해 OS 창 사각형을 만들고(`gpui-pre-windows-0.3.10/src/window.rs` `calculate_window_rect`, `WindowBorderOffset`), 그 결과 창 사각형이 가운데 놓이며 클라이언트는 위로 치우친다. (이 원인 분석이 맞는지 소스로 확인하라. 실제로는 `Bounds::centered_at`에 준 원점이 그대로 클라이언트 원점이 되어야 할 텐데 결과가 다르다 — 어디서 위치가 바뀌는지 찾는 것이 먼저다.)

## 요구 (core ORDER-02-R1 완료 기준)
1. 기록 없는 첫 실행: 클라이언트 1440×852, 클라이언트 중심과 작업 영역 중심 차이가 가로·세로 모두 1px 이하.
2. 크기를 바꾸고 다시 실행해도 1과 같다.
3. 최소 360×240 유지.
- 배율 100% 외(125%·150%·200%)에서도 같은 원리로 맞도록 고정 픽셀 상수(예: `+4`)로 때우지 않는다. 비대칭의 크기를 실제 값(gpui 내부 값, 또는 Win32 `GetSystemMetricsForDpi`/`AdjustWindowRectExForDpi` 등)에서 구한다.

## 제약
- 새 의존성 금지(`Cargo.toml` 변경 금지). Win32 호출이 필요하면 이 레포의 기존 FFI 방식(`src/state/win.rs` 참고)을 따른다. gpui가 이미 공개한 API로 되면 그것이 먼저다.
- I-6 밖은 고치지 않는다. 앱을 실행하지 않는다(`cargo run` 포함, 실측은 checker가 화면 차례를 받아 한다). 커밋하지 않는다.
- 계산을 넣으면 K-01 테스트를 고치거나 `#[test]`를 더해 "클라이언트 중심 = 작업 영역 중심"을 확인한다(비대칭 값이 있을 때 포함).
- 확인: `$env:CARGO_TARGET_DIR='D:\projects\workbench-gpui\target'`, `cargo build`, `pwsh -NoProfile -File tools/apply-manifest.ps1`, 관련 `cargo test <filter>`, `cargo clippy --all-targets -- -D warnings`.

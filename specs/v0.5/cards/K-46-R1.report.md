## 1. 배경
Zed는 코드 블록 배경에 `editor_background`(C-41)를 쓴다. 앱의 `theme.background`가 이미 `editor.background`(없으면 같은 appearance의 One, 그다음 고정값 — `theme::project`)라 코드 블록 `StyleRefinement`에 `.bg(theme.background)`를 덧입혔다(One Dark #282c33, 테스트로 확인). 텍스트 뷰 공용 `code_background`(= muted)는 표 머리줄 등이 쓰는 값이라 바꾸지 않았고, 인라인 코드는 따로 지정한 `foreground.opacity(0.08)` 그대로다.

## 2. 간격 — 원인과 고친 곳 (한 곳)
- 원인: 텍스트 뷰(vendor `node.rs` 2646-2652, `gapped`)가 **마지막이 아닌 모든 블록 아래에 `paragraph_gap`(16)을 `pb`로 더한다**. 코드 블록은 거기에 `my(16)`(위·아래 여백)이 더해져 두 코드 블록 사이가 아래 여백 16 + 간격 16 + 위 여백 16 = **48**이었다.
- Zed 소스(`markdown.rs` 4304dec 사본, 값만): 코드 블록은 위·아래 여백 16(미리보기 덮어쓰기 382-383)이고 블록 사이 간격은 따로 없다. 그런데 V3 캡처의 Zed는 코드 블록 사이가 16이고, 제목(아래 12) 다음 코드 블록 위가 28(= 12 + 16)이라 **코드 블록 위 여백만 효과가 있고 아래로는 0**인 모양이다(캡처 열 픽셀과 소스 값을 맞춰 본 결론; 아래 여백이 안 먹는 Zed 쪽 이유는 소스에서 못 찾았다).
- 고침: 코드 블록 `StyleRefinement`을 `my(16)` → `mt(16)`(toml `code_block.margin_y`) + `mb(-16)`(= -`paragraph_gap`, 뷰가 더하는 간격을 되돌림)으로. 연속 코드 블록 사이 = -16 + 16 + 16 = **16**. 테스트가 이 합을 toml `markdown_preview["code_block.margin_y"]`와 `assert_spec`으로 대조하고, 아래 여백이 `-PARAGRAPH_GAP`임도 확인한다(간격 값이 바뀌면 같이 틀어지지 않게).
- 문단·제목·목록·인용 사이 간격은 코드 블록의 스타일만 건드렸으므로 그대로다.

## 3. 알림 — 코드 블록과 이웃한 블록 간격이 바뀐다 (V3 확인)
코드 블록 **아래** 간격이 32(아래 여백 16 + 간격 16)에서 0으로 줄고(Zed 모양), 위는 문단 → 코드 32·제목 → 코드 37 그대로다. 코드 블록 다음 블록이 제목이면 제목의 위 여백 계산(vendor가 "앞 블록이 문단 간격을 이미 줬다"고 가정)이 그대로라 Zed 값보다 16 작을 수 있다 — 캡처의 "Table" 제목 앞 간격이 그것이다. 코드 블록이 문서의 마지막이면 뷰가 간격을 안 주므로 그 블록 아래 16이 컨테이너 안쪽 여백으로 겹친다(스크롤 끝에서 아래 여백이 16 짧아 보일 수 있음). 이웃 간격이 Zed와 다르면 leader가 V3 수치를 주면 맞춘다(vendor를 안 고치는 한 이 곱셈 구조 안에서만 조정 가능).

## 2. 구현 요약

- `QueryResources`가 언어별 주입 설정(`injection.content`/`injection.language` 캡처 인덱스, 패턴별 `injection.language` 값과 `injection.combined`)을 쿼리 컴파일 때 한 번 만든다. 파일 목록은 `query_files(id)`로 모아 `load_queries`와 같은 순서를 쓴다.
- `Layer`(언어 id, 깊이, 트리, 호스트 바이트 범위, combined 여부, 자식 층)의 트리: 루트 = 파일 자신의 언어, 자식 = 주입 층. 호스트 범위는 내용에 펜스 언어 글자(`info_string`)를 포함해 언어 글자를 고쳐도 그 층이 갱신된다.
- `SyntaxHighlighter::runs`: 보이는 범위와 겹치는 층의 `highlights` 캡처를 모아 병합하고 `style_runs`로 바이트 단위 스타일을 만든다. 층마다 테마별 캡처→스타일 표를 한 번만 계산해 둔다(`CaptureStyles`).
- 언어가 없는 주입(`comment`, `toml`, `latex`, `sql`, `graphql`, `doxygen` …)은 층을 만들지 않아 바깥 색이 그대로다.

## 3. 편집 후 갱신 (성능)

- `edit`: 모든 층의 트리와 호스트 범위에 `Tree::edit` 적용, 편집된 바이트 범위를 기록. `reparse`: 루트를 이전 트리로 증분 파싱 → **트리 변화 범위 ∪ 편집 범위**를 "바뀐 범위"로(글자 하나만 늘리는 편집은 트리 변화로 안 잡혀서 합쳐야 한다. 처음 구현에서 코드 블록 안 편집 뒤 색이 안 갱신되는 버그를 테스트가 잡았다) 두고, 바뀐 범위에 닿는 자식 층만 버리고 그 범위(±1바이트)에서만 주입 질의를 다시 돌린다. 새 층은 같은 언어·겹치는 범위의 버린 층 트리를 이전 트리로 삼아 증분 파싱하고, 트리가 같으면 그 아래 층은 건드리지 않는다. `injection.combined` 패턴이 있는 층은 층 전체를 다시 본다(마크다운 문단 하나 크기).
- 측정(**디버그 빌드**, 최적화 없는 C 파서; 합성 마크다운 283 KB, 제목+문단+Rust 코드 블록, 층 6200개; 측정용 임시 테스트와 계측은 지웠다):

| 구간 | 시간 |
|---|---|
| 첫 전체 파싱(루트 + 6200개 층) | 약 2.4초 (루트 0.45초 + 층 생성 약 2.0초) |
| 편집 1회 재파싱 | 약 210 ms — 거의 전부 마크다운 **루트**의 증분 재파싱(약 200 ms). 트리 변화 계산 약 9 ms, **주입 층 갱신 약 1 ms** |
| 보이는 4 KB 구간의 `styles()` | 약 8 ms (추가 층 합쳐서) |

  주입 때문에 늘어난 편집 비용은 약 1 ms로 작고, 편집당 지연의 대부분은 K-42B부터 있던 루트 파싱이다. **릴리스 빌드 수치는 없다**: 디스크가 가득 차(8장) release 빌드가 실패했다. 릴리스에서는 훨씬 빠를 것으로 예상하지만 측정하지 않았으니 V3에서 대용량 마크다운으로 확인해야 한다.
- `shortcut:` 주석 3곳: UI 스레드 파싱(첫 파싱이 큰 파일에서 한 프레임을 막음, 배경 파싱은 후속), 깊이 6 제한, 편집마다 모든 층의 `Tree::edit`(층 수만큼; 측정상 루트 재파싱에 비해 작음. 층이 아주 많아 막히면 편집 로그를 쓰는 지연 적용으로 바꿀 수 있다 — 한 번 시도했다가 측정에서 이득이 없어 되돌렸다).

## 4. 마크다운 (K-42B 보고 3장의 이월분)

- 인라인(`markdown-inline`): 굵게 `emphasis.strong`, 기울임 `emphasis`, 코드 스팬 `text.literal`, 링크 텍스트 `link_text`, 링크 주소 `link_uri`가 이제 칠해진다. 제목 줄 안의 `*x*`는 제목(`title`)보다 위에 기울임이 온다(주입 층이 깊음).
- 코드 블록: 펜스 `info_string`의 언어 글자(`rust`·`ts`·`py` …, 대소문자 무시, suffix 가능)로 해당 언어 층. 모르는 언어(`foo`)는 평문. `html_block` → HTML, `---` 머리말(`minus_metadata`) → YAML, `+++`(`plus_metadata`) → TOML은 없는 언어라 주입 안 됨, 표 셀(`pipe_table_cell`) → 인라인.
- 인라인 안의 HTML 태그(`html_tag`)는 combined HTML 층.
- 마크다운 화면(K-44 이후)의 Zed 대비 차이는 7장의 V3에서 확인한다.

## 6. 알려진 한계

- 쿼리의 `injection.host`·`injection.include-children`은 해석하지 않는다(대상 언어 sql/doxygen이 표에 없어 무효과; 표가 늘면 다시 볼 것).
- JSDoc은 K-43C 보고대로 한 줄 `/** x */`를 오류로 파싱한다(문법 성질). Zed도 같은 쿼리·문법이라 같은 현상일 것으로 보며 V3에서 한 줄/여러 줄 JSDoc 주석을 Zed와 대조해야 한다.
- 모든 층의 트리를 편집마다 갱신하고 첫 파싱은 UI 스레드(위 3장).

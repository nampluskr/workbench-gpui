# K-01 — 시작 창 1440×852, 작업 영역 가운데

## 요구 (`specs/v0.5/SPEC.md` R-6 = core I-6)
- 앱 시작 때 메인 창 클라이언트 영역을 논리 1440×852로 연다.
- 작업 표시줄을 뺀 작업 영역(work area)의 한가운데에 둔다.
- 최소 크기 360×240(이미 `src/ui/metrics.rs` `WINDOW_MIN_SIZE`, G-103). 바꾸지 않는다.
- 마지막 창 크기는 기억하지 않는다. 매번 1440×852. (지금 코드에 창 크기 저장이 없는 것으로 보인다. 있으면 알려라.)
- Zed(1536×1095, 크기 기억)에 맞추지 않는다. I-6 값이 toml보다 우선한다(core D-12, AGENTS 3장 예외).

## 현재 코드
- `src/ui/mod.rs` `window_options()`(642행)가 `window_bounds`를 정하지 않아 gpui 기본 크기로 연다. `run()`에서 `gpui_kit::open_window(window_options(), cx, ...)`로 연다.

## 할 일
1. 1440×852 상수를 `src/ui/metrics.rs`에 두고(주석 출처 "core v0.5 ITEMS I-6"), `window_options`에서 `window_bounds`를 정한다. gpui의 기존 기능(예: `WindowBounds::Windowed(Bounds::centered(...))`)을 먼저 쓴다.
2. 가운데 기준이 **작업 영역**(작업 표시줄 제외)인지 모니터 전체인지 gpui 소스(Windows 플랫폼 코드)를 읽어 확인한다. 모니터 전체 기준이면 작업 영역 기준이 되게 최소 코드로 맞춘다(Windows API는 이미 의존하는 crate 안에서만; 새 의존성 금지 — 필요하면 멈추고 [BLOCKED]).
3. 크기가 클라이언트 영역 기준인지 확인한다(이 앱은 OS 타이틀 바를 숨긴 창이다).
4. 비자명한 계산(작업 영역 가운데 좌표 등)을 직접 넣으면 `#[test]` 하나를 남긴다.
5. 확인: `cargo build`, `pwsh -NoProfile -File tools/apply-manifest.ps1`, 관련 테스트 `cargo test <filter>`, `cargo clippy --all-targets -- -D warnings`. `$env:CARGO_TARGET_DIR='D:\projects\workbench-gpui\target'`.
6. **앱을 실행하지 않는다**(`cargo run` 포함, 화면 검증은 checker가 차례를 받아 한다). I-6 밖은 고치지 않는다. 커밋하지 않는다. 의존성을 바꾸지 않는다.

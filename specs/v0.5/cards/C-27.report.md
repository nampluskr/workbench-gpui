## 3. 3대 실패 원인 정밀 구분 (앱 결함 vs 스크립트 결함)

### 1. `app-settings-comments`
- **저장 트리거**:
  - `src/ui/settings.rs:195-203`: `NumberInput`의 `InputEvent::Change` 이벤트 구독 시 `this.change()` -> `save()` -> `write()`를 동기적으로 호출하여 파일에 즉시 기록함. Enter나 blur 대기 없이 즉시 저장되는 구조임.
- **원인 분석**:
  - `app-settings-window.png` 픽셀 분석 결과, 상단 Y=0..242가 완전한 백색 공백이며 모든 UI(사이드바 검색칸 Y=372, 본문 설정 칸 Y=270~)가 창의 세로 중앙에 몰려 있음.
  - `src/ui/settings.rs:254`의 `h_flex().size_full()`이 기본 교차축 정렬인 `items_center`로 동작하여 750px 창 내부에서 자식 요소들이 수직 중앙 정렬됨.
  - 스크립트는 SPEC R-2 정상 좌표(검색칸 Y=56, 버퍼 폰트 Y=185)를 클릭했으나, 해당 위치는 빈 공간이었음. 결과적으로 `InputEvent::Change`가 전혀 발생하지 않아 저장이 트리거되지 않음.
- **결론**:
  - **앱 결함**: `src/ui/settings.rs:254`: 최외곽 `h_flex()`에 `.items_start()` 미적용 및 상단 패딩 누락으로 컨트롤이 중앙 정렬됨. 기대 수정: `.items_start()` 적용 및 상단 y=33 레이아웃 정합.
  - **스크립트 결함**: `tools/measure/order06-r1-v3.ps1:852, 915`: 앱의 실제 포커스 상태나 캡처 변화를 확인하지 않고 좌표 맹목 입력(Blind Input) 진행.

### 2. `app-keymap-editor`
- **저장 경로**:
  - `src/ui/keymap.rs:140`: `dirs::config_dir().map(|dir| dir.join("workbench-gpui").join("keymap.json"))`로 Windows 환경에서 `%APPDATA%\workbench-gpui\keymap.json`으로 정확함.
- **원인 분석**:
  - 스크립트 `tools/measure/order06-r1-v3.ps1:1050-1053`에서 Save 버튼 클릭 좌표를 `$saveBtnX = $mOrigin.X + 280, $saveBtnY = $mOrigin.Y + 805`로 계산함 (화면 좌표 520, 895).
  - 윈도우 클라이언트 기준 X=280을 클릭했으나, `layout.json` 상 좌측 사이드바 폭이 300px(`sidebar w=300`)이며 에디터 영역(`active-item`)은 X=300부터 시작함.
  - 따라서 X=280은 사이드바 내부 배경을 클릭한 것이며, 에디터 내부의 Save 버튼(X >= 308)을 전혀 클릭하지 못함.
  - 클릭이 빗나갔으므로 `save()` 리스너가 호출되지 않아 파일이 생성되지 않음.
- **결론**:
  - **앱 결함**: 없음. 저장 로직, AST jsonc 생성, 파일 기록 경로는 정상 구현됨.
  - **스크립트 결함**: `tools/measure/order06-r1-v3.ps1:1050`: 사이드바 폭(300px) 오프셋을 반영하지 않고 X=280을 클릭하여 Save 버튼 클릭 실패.

### 3. `app-tab-cycle`

  - 그 결과 `tree-row-01`이 나타나지 않아 assertion 타임아웃 오류 발생.
- **결론**:
  - **앱 결함**: 없음.
  - **스크립트 결함**: `tools/measure/order06-r1-v3.ps1:530`: 도구 탭 이후의 폴더 목록 상태(`folder-row-00`)를 인식하지 않고 `status-btn-project-panel`을 클릭하여 dock을 닫아버림. 폴더 클릭 또는 폴더 재활성화 조작 누락.

## 원인과 수정

`src/ui/pane_group.rs::PaneGroup::new_editor`는 각 탭 에디터에 `set_scrollbar_renderer(Some(Rc::new(editor_scrollbar)))`를 설치한다. `src/ui/pane.rs::editor_scrollbar`는 기존에 axis와 폭만 지정했다.

설치된 gpui-base 0.8.1 `src/scrollbar.rs::Scrollbar::prepaint`는 생성 시 mode가 없으면 공통 테마의 `scrollbar.mode()`를 사용한다. 기본 `ScrollbarMode`는 `Scrolling`이며, `wants_visible`은 스크롤 시점/idle 시간에 따라 표시를 결정한다. 단순 편집 영역 호버는 `Scrolling` 모드의 표시 조건이 아니다. 이것이 호버만으로 나타나지 않고, 스크롤 후에도 숨겨지는 코드상 원인이다.

에디터 전용 `editor_scrollbar`에 `.mode(gpui_kit::base::ScrollbarMode::Always)` 한 줄을 추가했다. 공통 테마의 스크롤바 모드는 바꾸지 않았으므로 파일 트리 등 다른 영역에는 적용되지 않는다. 이 함수의 호출부는 위 탭 에디터 등록 지점 하나다.

## overflow와 페이드 조건 확인

- `gpui-base/src/input/base/element.rs`의 EditorScrollbar는 soft wrap이면 `ScrollbarAxis::Vertical`, 아니면 `Both`를 context에 전달한다(274~278행). 기존 `.axis(context.axis())`를 유지했다.
- `gpui-base/src/scrollbar.rs::prepaint`는 축마다 `scroll_area_size <= scroll_viewport_size`이면 `continue`하여 막대를 만들지 않는다. `Always`도 이 overflow 조건을 통과해야 한다. 따라서 세로는 스크롤할 내용이 있을 때 계속 보이며, 가로는 wrap이 꺼져 있고 가로로 넘칠 때만 보인다.
- `wants_visible`에서 `Always`는 마우스 위치·최근 스크롤 시각과 무관하게 true이며, prepaint의 visibility enter/exit duration도 ZERO를 사용한다. 기존 폭 15px와 테마 색·엄지/드래그 로직은 그대로 사용한다.
- 스크롤바가 계속 안 보이는 다른 원인까지 실제 화면에서 배제한 것은 아니다. 위 표시 정책 수정 뒤의 실제 렌더링 판정은 V3로 남긴다.

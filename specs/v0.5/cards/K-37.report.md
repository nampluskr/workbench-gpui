## 수정과 테스트

- `follow`는 선택 또는 탭 수 변경 때 `pending`에 활성 탭 인덱스를 저장한다. 같은 상태로 다시 렌더되어도 대기 요청을 지우지 않는다. 빈 pane은 취소한다.
- 행의 기존 `on_children_prepainted`에서 `after_layout`이 대기 요청을 한 번 소비하여 `scroll_to_item`을 저장하고 `window.refresh()`로 다음 프레임을 요청한다. gpui의 listener 호출은 `div.rs:2099`로 viewport 갱신 뒤다. 다음 prepaint에서는 직전 배치로 갱신된 viewport와 overflow로 요청을 처리한다.
- 소비 뒤 `pending=None`이고 `seen`이 같으면 재요청하지 않는다. 사용자의 휠 위치를 렌더마다 활성 탭으로 되돌리지 않는다. 더 최신 선택이 배치 전 들어오면 대기 인덱스를 교체한다.
- 기존 `active_tab_scrolls_into_view_only_on_change` 테스트에 대기 유지, 완료 시 1회 소비, 완료 뒤 동일 선택에서 재요청 없음, 새 선택으로 교체, 빈 pane에서 취소를 추가했다. gpui가 필요한 새 계산 로직은 없어 별도 순수 함수를 만들지 않고 실제 상태 메서드를 테스트했다.

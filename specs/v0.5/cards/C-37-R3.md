# C-37-R3 — 4차(run4) 단계 버그: 입력이 다른 창으로 감, 판정 하드코딩, 단계 간 상태 오염
4차(`measure-ORDER-09-run4`) leader 판정: 셋업·step1·step2는 유효. 나머지는 스크립트 문제로 무효.
**가장 중요(안전)**: step5 마지막 `MouseBack()` 때 앱 창이 앞에 없어 **입력이 사용자 브라우저로 갔다**(`app-step5-nav-step10-mouseback.png`에 웹 페이지가 찍힘). 앱 밖으로 입력이 가는 일은 다시 있으면 안 된다.
1. **모든 키·마우스 입력 직전에** `GetForegroundWindow() == $script:appHwnd`이고(마우스는 추가로) 커서 위치가 앱 창 클라이언트 영역 안인지 확인하는 `Assert-AppInput` 함수를 두고, 하나라도 아니면 입력을 보내지 않고 그 단계를 `FAIL: 앱이 앞 창 아님`으로 끝낸다(다시 앞으로 가져오기 1회 시도는 허용, `Ensure-Foreground`가 실패하면 입력 금지). 모든 SendInput·Click·DoubleClick·Wheel·Key·MouseBack 호출 경로가 이 함수를 지나게 한다. 셋업의 `WARN: Failed to set foreground` 뒤에도 입력이 나갔으니 그것도 막는다.
2. **판정 하드코딩 제거**: `[RESULT] stepN: PASS`가 측정 없이 나온다(step3은 `wheel delta=0 px`인데 PASS). 각 판정은 측정값으로 계산하고, 값과 기대값을 같은 줄에 적는다. 판정을 못 하면 `UNMEASURED`.
3. **단계마다 새 세션**: 한 실행에 여러 단계를 이어 돌리지 말고, leader가 `-Steps step1`처럼 단계마다 새 Out으로 따로 돌릴 수 있게 하고(이미 됨) 스크립트 도움말에 그 방식을 기본으로 적는다. 단계 시작에 `Esc` 두 번(팝업·메뉴 닫기) 후 스냅샷에서 팝업 박스가 없는지 확인.
4. **step3**: ① 휠은 탭 줄 위(덤프 `tab-label-00` 또는 활성 탭 박스의 y, 탭 줄 x 가운데)에서 보낸다 — 4차는 트리 위에서 굴러 트리가 스크롤됐다. 휠 전후 같은 탭 박스의 x 차이를 잰다(기대 약 80). ② 활성 탭 보이기는 탭을 연 직후 스냅샷과 그 다음 스냅샷(최대 1초) 둘 다 기록(4차: 직후 캡처에서는 활성 `panels.ts`가 안 보이고 나중 캡처에서 보였다 — 몇 프레임 늦는지 기록). ③ `Ctrl-PageUp` 전에 편집기를 클릭해 포커스를 준다(4차는 활성 탭이 바뀌지 않았다). 바뀐 활성 탭 이름과 그 탭 박스가 탭 줄 안에 있는지. ④ 마지막 탭 오른쪽 끝 x와 오른쪽 버튼 묶음 왼쪽 x 사이 간격을 잰다(4차 캡처에서 약 24px 빈 자리 — Zed `zed-overflow.png`는 탭이 버튼에 바로 잘림).
5. **step4**: 앞 단계가 탭을 많이 열어 두지 않게 새 세션에서 시작. AGENTS.md 1행 → 덤프 `breadcrumb-path`·`breadcrumb-seg-01` 박스와 캡처 잘라낸 그림(툴바 줄 y 범위)을 남긴다. 5행으로 커서 이동은 편집기 클릭 뒤 `Ctrl-Home` + `Down` 4번. 분할은 분할 버튼 메뉴 대신 `Ctrl-\` 키(메뉴가 열려 남지 않게)로. 두 폴더는 지금 방식 유지.
6. **step5**: 새 세션. 9단계마다 상태 바 `줄:열` 박스(덤프 이름 확인)와 활성 탭 이름을 덤프에서 읽어 로그에 표로(기대값 열 포함). 66행 점프 대체는 `Ctrl-End` 대신 R-10과 같은 효과의 10줄 이상 이동(예: `PageDown`) — 무엇을 썼는지 기록. 마우스 뒤로는 1항 확인을 지난 경우에만.
확인: 파서 구문 검사 0, `-DryRun` 전체, run4 `app-stdout.txt`로 `-ReplayStdout`(step3 탭 박스 좌표·휠 위치 계산이 탭 줄 안인지). 앱·session 실행 금지. 기존 폴더 지우지 않음. 보고 `specs/v0.5/cards/C-37-R3.report.md`. 답은 경로만.

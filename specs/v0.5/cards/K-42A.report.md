## 언어 표와 로더

- `src/ui/syntax.rs`에 SPEC R-15/W-48의 24개 언어 이름·suffix·파일 이름·first_line_pattern·grammar·query 폴더 ID를 정적 표로 두었다. 숨김 주입 언어도 포함한다. query 폴더는 id와 같다.
- 파일명/접미사는 대소문자를 보존하고 가장 긴 일치를 먼저 쓴다. `tsconfig.json`은 JSONC, `.env`는 Env, COMMIT_EDITMSG는 Git Commit, 대문자 `.C`는 C++다. 매칭되는 이름이 없으면 첫 줄 정규식으로 판정한다. 모르는 언어는 None이다.
- 문법 연결은 Rust, JSON, JSONC, Markdown, Markdown-Inline의 5개 설정만이다. JavaScript→TSX·Env→bash·Zed Keybind Context→rust 등의 전체 메타데이터는 유지하되 이번 카드에서는 이들의 문법을 열지 않는다.
- 앱 시작에서 OnceLock 캐시를 초기화하여 자기 레포 resource root의 `resources/zed-languages/<id>/`만 읽는다. 외부 Zed 설치·확장 폴더나 config.toml은 읽지 않는다. 경로는 기존 로컬 theme/icon 리소스와 같은 CARGO_MANIFEST_DIR 기준이다. 배포 리소스 루트 확장은 이번 카드에서 추가하지 않았다.
- 문법별로 Parser::set_language 후 필요한 highlights/injections/outline을 컴파일한다. JSON은 H/O, Markdown-Inline은 H/I, 나머지 연결 언어는 H/I/O다. 한 파일이라도 빠지거나 컴파일이 실패하면 해당 언어 query set 전체를 설치하지 않는다. 다른 언어는 계속 로드한다.
- 캐시는 앱 시작 시 한 번 생성되며 누락/오류는 한 번의 경고로 묶는다. query가 없으면 조회 결과가 None이어서 평문으로 처리할 수 있다. 아직 에디터의 텍스트·선택·undo·저장 경로에는 연결하지 않았다.
- K-42B 소비 전이라 metadata의 suffix/first_line·언어 탐지 함수·query 조회 API는 일반 빌드에서 아직 호출되지 않는다. 이 카드에서 요구한 기반 API를 유지하기 위해 해당 지점에만 `cfg_attr(not(test), expect(dead_code, reason=...K-42B))`를 두었다. 테스트 빌드에서는 기대 경고 처리를 제외하여 실제 사용을 검사한다. K-42B에서 연결하며 제거해야 한다. clippy allow는 추가하지 않았다.

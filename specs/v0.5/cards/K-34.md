# K-34 — 경로 줄(breadcrumb): 경로 + 마크다운 제목 계층(I-12)
Zed 기준: `specs/v0.5/SPEC.md` R-12 "Zed 확인(tauri, 2026-11-07)" 표 전체(근거 `cards/C-36.report.md`). 현황: `K-31.report.md` I-12 절(`layout.rs:543-566` `markdown_toolbar`, `pane_view.rs:306-319`).
**범위(core [DECISION]): 경로 + 마크다운 제목 계층까지. 코드 파일은 경로만(심볼 계층은 Phase 11).**
1. 툴바를 모든 단일 파일 편집기 탭으로 넓힌다(`markdown_toolbar` → 편집기 툴바). Project Search·Diagnostics·미리보기 탭에는 지금처럼 두지 않는다(그 탭들의 툴바는 그대로). 크기는 기존 `toolbar.*` toml ID 그대로. 오른쪽 미리보기(eye) 버튼은 마크다운일 때만, 그 외 버튼은 넣지 않는다.
2. 왼쪽 글자: 경로 조각 + 제목 조각을 ` › `로 잇는다.
   - 경로: 폴더 하나면 루트 기준 상대 경로, 폴더가 둘 이상이면 루트 폴더 이름부터(`workbench-tauri\AGENTS.md`). 경로는 **한 조각**(디렉터리마다 나누지 않음), 구분자 `\` 그대로(I-20). 폴더 밖 파일은 Zed 소스(`editor.rs:11685`, `buffer.rs:5533`)대로 — 확인해 보고.
   - 마크다운 제목: 커서가 있는 줄을 포함하는 제목 계층 전체를 `#` 접두 그대로(`# AGENTS › ## 레포 규칙`). 커서가 첫 제목보다 위면 경로만. 새 의존성 없이 줄 스캔 순수 함수로(펜스 코드 블록 안 `#` 제외, ATX 제목만). 한계는 `shortcut:` 주석(예: setext 제목 미지원).
   - 조각이 12개를 넘으면 가운데를 `⋯`로(C-36 `element.rs:7141, 7170`) — 마크다운 깊이로 거의 안 나오지만 함수에 넣는다.
3. 색·글꼴: `›`는 placeholder 색(테마의 해당 토큰). 경로 글자색, 제목 글자색(Zed는 문법 색 — 이 앱의 마크다운 하이라이트에 제목 색 토큰이 있으면 그것, 없으면 보고), 글꼴·크기는 Zed 소스(`%TEMP%\zed-src-4304dec7`, 읽기만, 코드 복사 금지 — `crates/breadcrumbs`, `editor/src/element.rs` 근처)에서 값을 확인해 기존 toml ID가 있으면 쓰고, 없으면 상수로 두고 보고에 "toml ID 필요"로 적는다(leader가 writer에게 넘김).
4. pane마다 자기 활성 탭의 커서 기준, 커서가 바뀌면 다시 그린다(분할 두 pane이 서로 다른 제목을 보일 수 있어야 함).
5. 레이아웃 덤프 probe 이름 추가: `breadcrumb`(줄 전체), `breadcrumb-path`, `breadcrumb-seg-0x`(첫 몇 개) — V3에서 쓴다.
6. 덤으로(작게): K-33 상수 주석의 ID를 `tab.scroll.wheel_step`로 고치고(W-42가 `[tab]` 섹션에 올림) 그 ID로 `assert_spec` 테스트를 붙인다.
7. 테스트: 제목 계층 함수(펜스·계층 건너뜀 `#`→`###`·첫 제목 위), 경로 문자열(폴더 하나/둘), `⋯` 줄임.

## A. Replace는 버퍼만 바꾼다 (동작 변경)

- `SearchView::process`의 바꾸기 분기에서 `save_tab` 호출(디스크 저장)과 그 뒤 처리(`saving` 필드, 저장 결과별 중단·닫힘 처리)를 모두 뺐다. 이제 파일을 탭으로 열고(또는 이미 열린 탭을 쓰고) `project_search::replacement`로 만든 새 텍스트를 `ws.group.fill`로 버퍼에 넣고 `on_edit`로 탭을 수정됨(dirty)으로 표시하는 데서 끝난다. 디스크에는 쓰지 않는다. Replace Next(현재 일치 하나)·Replace All 둘 다 같은 경로다.
- 유지한 보호: 검색 스냅샷과 현재 편집기 내용이 다르면 "File changed since search; search again…"으로 중단하고 남은 배치를 비운다(`replacement`의 비교). 닫힌 탭·읽기 실패·정규식 오류에서도 남은 배치를 중단한다. 검색은 열린 문서의 현재 메모리 내용을 대상으로 하므로 미저장 편집이 있어도 일치 범위가 버퍼 기준으로 맞는다. 결과 한도 밖 일치를 몰래 바꾸지 않는 동작도 그대로다.
- 바꾼 뒤에는 열린 버퍼 기준으로 자동 재검색해 결과가 최신이 된다(`start()`는 열린 버퍼를 읽는다). 그래서 같은 파일에서 Replace Next를 이어서 눌러도 스냅샷 충돌이 나지 않는다.
- 안내 문구: Zed 소스를 이 PC에서 볼 수 없어 지어내지 않았다. 기존 "Replacement saved; search again to refresh results"에서 "saved"를 빼고 자동 재검색이 되므로 뒷절도 뺀 `Replacement applied`를 쓴다(재검색이 끝나면 한 번 보인다).
- 테스트 `k29_replacement_does_not_touch_the_disk`: 임시 파일에서 검색 → `replacement`로 한 건·전체 바꾼 텍스트를 계산 → 디스크 파일 바이트가 그대로임을 확인한다. 버퍼가 바뀌는 것과 dirty 표시는 기존 `pane::tests::edit_marks_dirty`(`on_edit` → `dirty`)가 덮고, `fill`·`on_edit` 호출 자체는 gpui 컨텍스트가 필요해 코드 확인이다.

## B. 검색 툴바 뒤 아이콘 x

Zed 캡처 잉크 x에서 박스를 역산해 기존 toml 값으로 설명되는 구성을 찾았다(입력 박스 끝 1167).

| 항목 | 박스(계산) | Zed 잉크 | 설명하는 값 |
|---|---|---|---|
| 필터 | 1175–1197 | 1179–1192 | 박스 끝 1167 + `editor["search_bar.gap"]` 8 |
| 바꾸기 | 1199–1221 | 1204–1216 | 필터 끝 + 2 (잉크 pitch 24.5 = 22 + 2) |
| ‹ | 1236–1252 | 1242–1247 | 바꾸기 끝 + 8(bar gap) + 1(구분 칸) + `search_results["matches.padding_left"]` 6 |
| › | 1256–1272 | 1262–1267 | ‹ 끝 + `buttons["gap"]` 4 (pitch 20 = 16 + 4) |
| `1/19` | 1280~ (잉크 1283) | 1283 | › 끝 + `editor["search_results_count.margin_left"]` 8, 최소 폭 `count.min_width` 40 |

- ‹ ›는 16×16(toml `buttons["height.none"]`)로 줄였다. 토글은 22 그대로.
- 값으로 설명 안 되는 것(추정값이 아니라 캡처에서 읽은 값으로만 둠): 토글 사이 2(잉크 pitch 24.5에서 역산, 반올림), ‹ 앞의 1px 구분 칸(tauri의 `border-left`와 같은 폭, 선은 그리지 않고 투명).
- 뒤 컨트롤 고정 폭은 22+2+22 + 8 + (1+6+16+4+16+8+40) = 145, 입력 오른쪽 빈 공간 `SEARCH_RIGHT_RESERVE`는 112로 다시 맞췄다(1432 − 112 − (8+145) = 1167). 둘째 줄(Include·Exclude·Replace)도 같은 폭을 쓰므로 같은 끝에서 끝나고, 둘째 줄 아이콘 버튼도 간격 2다. `k27_search_toolbar_metrics_follow_spec`가 위 x 다섯 개를 상수로 계산해 확인한다.
- 켜진 토글의 배경은 그대로다(캡처 3차의 "켜짐 배경"은 필터가 켜진 상태라서다).

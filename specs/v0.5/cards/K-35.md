# K-35 — 뒤로·앞으로 이동 기록(I-10)
Zed 기준: `specs/v0.5/SPEC.md` R-10 "Zed 확인(tauri, 2026-11-07)" 세 표 전체(근거 `cards/C-36.report.md`, core [NOTICE]: tauri와 같은 규칙으로). 현황: `K-31.report.md` I-10 절(버튼·툴팁만, 동작·키·기록 없음, 바꿀 곳 1~3).
1. **pane별 기록**(`pane.rs` `Pane`): 뒤 스택·앞 스택, 항목 = (파일 경로, 커서 위치). 상한 1024(넘치면 가장 오래된 것부터 버림 — tauri 확인 값, 상수에 주석). 분할 pane은 독립.
2. **기록 시점**(R-10 기록 규칙 표):
   - 탭을 떠날 때(다른 탭 활성화·파일 열기로 바뀔 때) 떠나는 탭의 커서 위치.
   - 같은 탭 안에서 커서가 **10줄 이상** 움직였을 때 움직이기 전 위치(Zed `MIN_NAVIGATION_HISTORY_ROW_DELTA` 10, 상수에 주석). 9줄 이하는 기록 안 함. 편집(타이핑)으로 생긴 커서 이동도 Zed처럼 같은 규칙이면 되는데, Zed 소스(`%TEMP%\zed-src-4304dec7` `crates/editor/src/navigation.rs:1567` 근처, 읽기만·복사 금지)를 보고 편집이 기록 대상인지 확인해 맞추고 보고.
   - 명시적 점프는 줄 수와 상관없이 항상: 이 앱에서는 Project Search 결과 열기(일치 위치로 이동)와 Diagnostics에서 위치로 이동이 있으면 그것. 다른 명시적 점프가 있으면 보고에 목록.
   - 새 위치로 기록하면 앞 스택을 비운다(Zed와 같게 — 소스로 확인).
3. **GoBack/GoForward**: 현재 위치를 반대 스택에 넣고 대상으로 이동. 대상 탭이 그 pane에 열려 있으면 활성화 + 커서 이동, 닫혔으면 그 경로로 다시 열고 위치로(Zed `workspace.rs:3300-3345`). 파일이 디스크에서 사라졌으면 그 항목을 건너뛰고 다음으로(Zed 동작 확인해 맞추고 보고). 커서 위치가 줄 수를 넘으면 끝으로 맞춤. 이동 자체는 기록하지 않는다.
4. **액션·키**: `pane::GoBack`·`pane::GoForward` 액션 정의·핸들러(기존 `on_split_*` 자리), `builtin.rs`에 Windows 키 `alt-left`·`alt--` → GoBack, `alt-right`·`alt-=` → GoForward(Zed `default-windows.json:516-521`, 같은 문맥 `Pane`). 마우스 뒤로/앞로 버튼(gpui `MouseButton::Navigate`)도 pane 영역에서. 메뉴 항목(`app_menu.rs:191-192`)이 액션으로 동작하게.
5. **버튼**: `layout.rs:457-470` 뒤로·앞으로에 on_click(그 pane 기준). 스택이 비면 흐린 비활성 모양(기존 split의 `opacity` 방식 그대로, 값은 이미 쓰는 상수), 누름 무시. 툴팁은 이미 있음("Go Back"/"Go Forward" + 키).
6. **테스트**(V1): 순수 기록 로직 — tauri 표의 9단계 시나리오(열기 → 66행 점프 → 뒤·뒤·앞·앞 → 9줄 이동 → 뒤가 1:1)를 그대로 재현하는 테스트, 10줄/9줄 경계, 1024 상한, 닫힌 탭 다시 열기(가능하면 `#[gpui::test]`, 아니면 상태 수준), 새 기록이 앞 스택을 비움.

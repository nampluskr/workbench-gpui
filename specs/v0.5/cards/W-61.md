# W-61 — docs/BUILD.md를 노트북에서 clone 후 그대로 따라 할 수 있게
사용자 요구: 사용자 개인 노트북에서 `git clone` 한 뒤 `docs/BUILD.md` 순서만 따라 배포본까지 만들 수 있어야 한다. **문서만** 고친다. 스크립트·코드·설정(`tools/`·`src/`·`.cargo/`·`.gitignore`·`Cargo.*`)은 고치지 않는다. 실제 빌드·clone 테스트는 하지 않는다(사용자 정정 — C-47은 시작 직후 멈췄고 만든 `%TEMP%` 복제 폴더는 leader가 지웠다).

leader가 코드를 읽어 확인한 사실(그대로 쓴다):
- fetch 세 스크립트는 모두 GitHub 공개 저장소의 고정 커밋·태그를 `%TEMP%`에 새로 sparse clone해서 받는다. 이 PC에만 있는 것(`D:\projects` 경로, `%TEMP%`에 미리 있던 Zed 사본, 설치된 Zed·확장 폴더, 로컬 캐시)에는 기대지 않는다. 필요한 것은 git, PowerShell 7, 네트워크(github.com)뿐이다. `fetch-zed-themes.ps1`의 `zed\zed.json`도 그때 받은 Zed 소스(`crates/theme/src/icon_theme.rs`)에서 만든다. 그래서 노트북에서 따로 준비할 복사본은 없다.
- 하드코딩 경로는 `tools/apply-manifest.ps1` 47줄 `C:\Program Files (x86)\Windows Kits\10\bin`(Windows SDK 기본 설치 경로, PATH에 `mt.exe`가 없을 때) 하나다. SDK를 기본 위치에 설치하면 그대로 된다.
- `Cargo.toml`의 git 의존성은 전부 GitHub 공개 저장소의 고정 rev, `[patch.crates-io] gpui-base`는 저장소 안 `vendor/gpui-base`(추적됨). `build.rs`는 저장소 안 `vendor/`만 읽는다. 문법 wasm 같은 다른 복사본은 없다.
- `CARGO_TARGET_DIR`는 사용자·시스템 환경 변수에 없다. 비워 두면 레포 `target\`을 쓴다. 지금 BUILD.md 3절 개발 빌드의 `$env:CARGO_TARGET_DIR = 'D:\projects\workbench-gpui\target'`은 이 PC(멀티 에이전트 공유) 전용이라 노트북 사용자에게 시키면 안 된다.
- 이 PC 값: `winget v1.29.380`, Rust `1.99.1`, Node `v22.22.3`(빌드에 필요 없음), tree-sitter CLI 없음(필요 없음).

할 것:
1. `docs/BUILD.md`를 고친다.
   - 맨 앞에 **노트북 처음부터 순서**(번호 단계, 명령 그대로 복사해 실행할 수 있게): 도구 설치 → 새 터미널 → `git clone https://github.com/nampluskr/workbench-gpui.git` → `cd workbench-gpui` → fetch 셋 → `pwsh -NoProfile -File tools/package-release.ps1` → 결과 위치. 각 단계에 예상 시간·확인 방법(예: fetch 끝 줄 출력, 스크립트 마지막 출력)을 근거 있는 것만.
   - 1절 도구 설치를 winget 명령과 버전으로:
     - Git: `winget install --id Git.Git -e`
     - PowerShell 7: `winget install --id Microsoft.PowerShell -e`
     - Visual Studio Build Tools 2022 + C++ 도구 + Windows SDK 10.0.26100: `winget install --id Microsoft.VisualStudio.2022.BuildTools -e --override "--wait --passive --add Microsoft.VisualStudio.Workload.VCTools --add Microsoft.VisualStudio.Component.Windows11SDK.26100 --includeRecommended"`
     - Rust: `winget install --id Rustlang.Rustup -e` 뒤 새 터미널에서 `rustup toolchain install 1.99.1`, `rustup default 1.99.1`(저장소에 `rust-toolchain` 파일이 없으므로 버전은 이렇게 맞춘다; 기본 대상은 `x86_64-pc-windows-msvc`).
     - 설치 확인 명령: `git --version`, `pwsh -v`, `rustc -V`, `cargo -V`, `rustup show active-toolchain`.
     - winget ID·Build Tools 구성 요소 ID는 이 PC에서 설치해 본 값이 아니므로 "이 PC에서 실행해 확인하지 않음"을 한 줄 적는다. Build Tools를 GUI로 설치할 때 고를 것(“C++를 사용한 데스크톱 개발”, Windows 11 SDK 10.0.26100)도 적는다.
     - Node·tree-sitter CLI 필요 없음은 유지.
   - 2절 fetch: 위 사실(공개 고정 커밋만, 이 PC 전용 사본에 기대지 않음, 노트북에서 따로 준비할 것 없음, 필요한 것 git·pwsh·네트워크)을 적는다. 회사망 등에서 github.com이 막히면 안 된다는 점.
   - 3절 개발 빌드: `CARGO_TARGET_DIR` 줄을 노트북 기준으로 고친다 — 기본은 설정하지 않음(레포 `target\`), 이 PC의 공유 경로는 "멀티 에이전트 데스크톱 전용" 참고로만.
   - 4절 결과 경로는 레포 기준 상대 경로(`<레포>\target\dist\...`)로. 크기는 2026-11-08 이 PC 값임을 밝힌다.
   - 5절 시간: 이 PC 측정값이고 노트북은 다를 수 있다는 점, 처음 빌드는 cargo가 crates·git 의존성을 받는 시간이 더해진다는 점. 깨끗한 clone 빌드 시간은 측정하지 않았다(사용자 정정으로 하지 않음).
   - 7절 제약에 "깨끗한 clone에서 BUILD.md대로 빌드해 본 기록 없음(코드 읽기로만 확인)"과 "`apply-manifest.ps1`은 Windows SDK 기본 경로 또는 PATH의 `mt.exe`가 필요" 추가. 디스크 여유(release target 약 4.5 GB, 이 PC 측정 — leader 값)도.
   - 8절 라이선스 주의, 9절 GitHub에 올리지 않는 것은 유지(9절 `.gitignore` 문장은 사실 그대로).
2. `specs/v0.5/PROGRESS.md` "버전 종료 뒤 사용자 요청 작업"에 항목 하나: 요청(세 지시와 정정 경과), 조치, 결과, 검증(코드 읽기), 상태. C-47 카드는 시작 직후 멈춤·복제 폴더 삭제로 적는다.
3. 다른 파일은 고치지 않는다.

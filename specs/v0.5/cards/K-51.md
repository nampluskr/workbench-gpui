# K-51 — 다른 PC에서 도는 배포본: resources 경로 한 곳, 정적 CRT, 패키지 스크립트
배경: release exe(41.38 MB)는 실행 중 resources를 `env!("CARGO_MANIFEST_DIR")` 절대 경로(`D:\projects\workbench-gpui\resources`)에서만 읽고, `VCRUNTIME140.dll`에 동적 링크한다. 그래서 다른 PC로 옮기면 아이콘·테마·문법 강조가 빠지거나 아예 안 뜬다. 최소 변경으로 고친다. 소스는 읽고 나서 판단한다(AGENTS.md 4.1).

1. **resources 경로 한 함수로**: 실행 코드(테스트 아님)에서 resources를 찾는 곳을 한 함수로 모은다 — `src/ui/theme.rs:40`, `src/ui/icon_theme.rs:56`, `src/ui/zed_icons.rs:12`(`res/`는 그 부모를 쓰니 그대로 맞게), `src/ui/syntax.rs:225`, `src/ui/extensions.rs:68`. 그 외 실행 코드에 같은 패턴이 있으면 함께(grep `CARGO_MANIFEST_DIR`).
   - 순서: `std::env::current_exe()`의 폴더 옆 `resources\`가 디렉터리면 그것, 아니면 지금의 `CARGO_MANIFEST_DIR\resources`(개발용). 한 번만 정하고(`OnceLock`) 정한 경로를 stderr에 한 줄 남긴다(예: `resources: <경로>` — 배포본 확인용).
   - 위치는 기존 공통 모듈 중 알맞은 곳(새 파일 만들지 않기). 테스트 코드의 `CARGO_MANIFEST_DIR`(`#[cfg(test)]`·`#[test]` 안)와 `include_str!`/`include_bytes!`는 그대로.
   - 테스트(V1): 선택 로직을 경로를 인자로 받는 작은 함수로 두고, "exe 옆 resources 있음 → 그것 / 없음 → 개발 경로"를 임시 폴더로 확인하는 `#[test]` 하나.
2. **정적 CRT**: 레포 안 `.cargo/config.toml`(새 파일)에 `[target.x86_64-pc-windows-msvc] rustflags = ["-C", "target-feature=+crt-static"]`. `Cargo.toml`·`Cargo.lock`은 바꾸지 않는다. rustflags가 바뀌어 공유 target 전체가 다시 빌드된다(오래 걸림, 잠금 대기면 기다린다). C 소스 크레이트(tree-sitter 등)나 미리 빌드된 라이브러리와 CRT가 어긋나는 링크 오류(LNK2038 등)가 나면 고칠 수 있는 가장 작은 방법을 쓰고, 안 되면 `[BLOCKED]`.
3. **`tools/package-release.ps1`(새 파일, PowerShell 7, 기존 tools 스타일)**:
   - `$env:CARGO_TARGET_DIR`가 비어 있으면 레포 `target`(스크립트 기준 `$PSScriptRoot\..\target`)으로 두고, 있으면 그 값을 쓴다. 상대 경로는 레포 루트 기준.
   - `cargo build --release`(스위치 `-NoBuild`로 건너뛰기) → `tools/apply-manifest.ps1 -Exe <release exe> -DumpTo <target>\manifest\release-manifest.xml`.
   - 실행 중 읽는 4폴더(`zed-icon-themes`·`zed-icons`·`zed-themes`·`zed-languages`)가 없으면 해당 fetch 스크립트 이름을 알려 주고 실패.
   - `target\dist\workbench-gpui\`를 새로 만들어(있으면 그 폴더만 지우고) exe + `resources\` 4폴더를 복사, `target\dist\workbench-gpui.zip`(Compress-Archive, 폴더째 들어가게)을 만든다. pdb·fonts·licenses·windows는 넣지 않는다(exe에 들어 있거나 빌드용).
   - 끝에 배포 폴더·zip 경로, 크기(MB), 파일 수를 출력한다.
4. 스크립트를 한 번 실행해 배포 폴더와 zip을 만든다. `dumpbin /dependents`(VS Build Tools의 `dumpbin.exe`)로 release exe에 `VCRUNTIME140.dll`·`api-ms-win-crt-*`가 없음을 확인해 보고에 목록을 붙인다.

확인: `cargo build`, `pwsh -NoProfile -File tools/apply-manifest.ps1`, 1의 테스트, `cargo clippy --all-targets -- -D warnings`, `pwsh -NoProfile -File tools/package-release.ps1`, dumpbin 결과. 앱 실행·커밋 없음(다른 경로에서 띄워 보는 확인은 checker 몫). 보고 `specs/v0.5/cards/K-51.report.md`(AGENTS.md 8장 형식 + exe 크기 전/후, 배포 폴더·zip 크기, dumpbin 목록, 전체 재빌드 시간). 답은 경로만.

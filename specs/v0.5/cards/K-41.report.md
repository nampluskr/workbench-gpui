## 4. 쿼리 복사와 로더 제안

- 제안 폴더 `resources/zed-languages/` 전체를 `.gitignore`에 추가한다. 스크립트 `tools/fetch-zed-languages.ps1`은 기존 fetch-zed-themes.ps1처럼 고정 Zed commit만 fetch하고 필요한 데이터 파일·라이선스를 복사한다. `.scm`, config 원문과 외부 라이선스 복사본은 커밋하지 않고 재생성 스크립트만 커밋한다. query 내용을 Rust `include_str!`에 넣지 않는다.
- `languages/<언어>/config.toml`, 존재하는 `highlights.scm`, `injections.scm`, `outline.scm`을 복사한다. `manifest.json`에는 source commit·언어/grammar 연결·각 파일 hash/존재 여부를 남긴다. 없는 outline/injections는 정상적인 선택 항목으로 기록한다. `locals.scm`은 대상 목록에서 확인되지 않아 만들지 않는다.
- 원본 위치는 내장 `crates/grammars/src/`다(ORDER의 옛 `crates/languages/src/*/config.toml` 경로를 그대로 쓰면 빠진다). HTML은 `extensions/html/languages/html/`와 `extensions/html/extension.toml`에서 가져온다. Rust 앱 코드나 language.rs 등은 복사하지 않는다.

앱 시작 때 자기 resource root만 읽어 config/query를 한 번 캐시한다. 현재 theme/icon 로더처럼 프로젝트 resource 위치를 재사용하고, 배포할 때는 자기 exe 옆 resources를 포함하는 위치 규칙을 명시한다. Zed 설치/확장 경로를 탐색하는 fallback은 금지한다. 폴더가 없거나 특정 query가 읽기/컴파일에 실패하면 해당 언어를 평문으로 처리하고 한 번 진단한다. 일부 파일 실패로 앱 전체를 중단하거나 원본/사용자 텍스트를 수정하지 않는다. 구현 검증에서는 실패한 대상 언어를 PASS로 집계하지 않는다.

## 5. 테마 규칙·캡처·주입·outline

- Zed `crates/syntax_theme/src/syntax_theme.rs:87–102`를 읽어 tauri R-15 규칙과 대조했다. 캡처 이름에서 점 단위로 뒤를 떼며 존재하는 가장 긴 syntax 키를 찾으면 같은 결과다. `keyword.control.import`는 keyword.control → keyword 순이며 `keywordish`를 keyword에 붙이면 안 된다. 어떤 키도 없으면 색을 부여하지 않는다. 이 매핑은 앱 syntax resolver에서 query의 capture_names별로 한 번 만들고 테마 세대가 바뀌면 갱신한다.
- Zed `crates/language/src/buffer.rs:5909–5922,5967–5972`는 매핑되는 캡처만 쌓고 맨 위 마지막 캡처 하나를 고른다. 앱의 styles 출력 전 구간 정규화에서 시작·끝/동일 시작의 query 캡처 순서를 보존한 이벤트 처리를 구현한다. 미매핑 capture가 외부 색을 지우지 않으며 인접 같은 style은 합치고 byte 구간은 UTF-8 경계에 둔다. 여러 겹의 style을 GPUI에서 나중에 합성하게 두지 않는다. 중첩·동일 범위·동일 시작·없는 키를 별도 V1 사례로 확인한다.
- injection은 query의 injection.language/content 및 설정 property를 읽어 포함 범위를 원래 buffer byte 위치로 유지한다. Markdown-inline, fenced code 언어 alias, HTML script/style, JS regexp/JSDoc을 대상으로 한다. 여러 조각 결합/중첩과 부모 색 유지도 확인해야 한다. query 원문은 바꾸지 않는다. tauri의 JavaScript 정규식 변환 문제(`(?s)`, `(?i:sql)`)는 Rust regex에는 해당하지 않지만 고정 core로 실제 Query 컴파일을 검사한다.
- Zed query에는 `sql`, `graphql`, `toml`, `comment`, `glsl`, `WGSL/WESL` 등 대상 24개 밖의 주입 이름도 나온다. 등록된 문법이 없으면 그 층만 생략하고 부모/평문을 남긴다. 이를 이유로 새로운 언어를 임의 추가하지 않는다. 설치 확장까지 포함한 재현이 필요하다는 판정이면 leader/core에 범위를 묻는다.
- outline은 기존 breadcrumb 경로 생성·세그먼트 생략을 재사용한다. 코드 파일에서 outline query의 item/name/context/annotation 구간을 읽고 cursor byte를 포함하는 item의 바깥→안쪽 계층을 구한다. 단순히 함수 이름만 가져오지 않고 Zed가 표시하는 문맥 문자열·주석/annotation 처리·문법 색 구간을 독립 구현한다. 심볼 밖은 경로만. `src/ui/pane_view.rs:324–351`, `src/ui/breadcrumb.rs`와 toolbar 렌더가 연결 지점이다. 현재 toolbar는 문자열 목록이므로 심볼 style run을 전달하는 작은 자료형 변경이 필요하다.
- preview는 component wrapper에 직접 public code_block_highlighter 전달 메서드가 없다. 하지만 `B/src/text/text_view.rs:30–84`의 공개 `TextViewDefaults::with_code_block_highlighter(...).install(cx)`가 있고 wrapper의 내부 Base TextView도 이 default를 읽는다. tree-sitter feature를 끈 경로에서 이 default를 설치하면 기존 component Markdown 렌더를 바꿀 필요 없이 같은 syntax 서비스를 쓸 수 있다. 안정적인 callback Arc를 유지하고 테마 세대 변경 시 교체하여 캐시가 갱신되게 한다. callback은 Send+Sync이므로 UI 전용 Rc 상태를 그대로 capture하지 않는다. editor용 parser는 공유하지 말고 block별 parser/cache를 쓴다.

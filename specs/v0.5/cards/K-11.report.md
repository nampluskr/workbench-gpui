## Settings 구조와 동작

- `%APPDATA%\\workbench-gpui\\settings.json`을 사용한다. 시작 시 읽고 파일·키가 없거나 null이면 기존 상수인 UI 16px·버퍼 15px을 기본값으로 쓴다.
- `Ctrl-,` 및 v 메뉴 Settings는 별도 OS 창을 연다. 열린 창 handle이 유효하면 앞으로 가져오고, 닫힌 창이면 새로 연다.
- 왼쪽은 `Search settings…`와 `Appearance` 하나, 오른쪽 상단은 `User`와 `Edit in settings.json`, 본문은 아래 네 행이다. 검색은 표시 이름·설명 및 설정 키에서 대소문자를 구분하지 않고 찾는다.
- JSONC 주석·끝 쉼표를 읽는다. 숫자는 유한한 양수이며 f32 픽셀 값으로 표현할 수 있어야 한다. 지원하지 않는 테마·잘못된 설정 파일은 덮어쓰지 않으며, UI 저장 오류는 Settings에 표시한다. 읽기 실패는 stderr에 기록하고 현재 적용값을 유지한다(시작 시 기본값).
- UI 변경은 디스크의 최신 객체를 다시 읽어 해당 키만 바꾸고 알 수 없는 키를 보존한다. 같은 디렉터리의 `settings.json.tmp`에 쓰고 sync_all 후 기존 replace_file로 원자 교체한다. 교체 실패 시 원본은 유지하고 오류를 반환한다. 저장 성공 후에만 적용한다.
- 기존 앱 데이터 디렉터리 감시 루프에 settings.json도 포함했다. 편집기나 외부에서 저장한 값도 읽어 적용한다. 감시의 기존 100ms poll·150ms quiet 처리를 재사용했다.
- UI 글꼴은 Theme.font_size와 열린 Workbench·Settings 창의 rem에 반영하며, 버퍼 글꼴은 Theme.mono_font_size 및 실제 탭 Editor의 text_size에 반영한다. 기존 고정 기본값 상수는 보존했다.
- `Edit in settings.json`은 파일이 없을 때 `{}`로 만들고 기존 편집기 탭을 연다. 활성 폴더가 없는 경우에는 사용자 폴더 목록에 등록하지 않는 별도 FolderWorkspace를 재사용 가능한 탭 문맥으로 둔다. 이 문맥의 미저장 파일도 기존 종료 확인 대상에 포함한다. 다른 폴더를 열어 설정 탭이 가려져도 종료 시 확인을 건너뛰지 않는다.

## Panel Layout

- Agentic을 제거했다. Classic은 항상 활성이고, dock이 열려 있으며 실제 유효 폭이 기본 폭과 같으면 체크한다.
- dock이 닫혔거나 실제 폭이 기본과 다르면 Classic 체크를 해제하고 체크된 비활성 Custom을 표시한다.
- Classic 클릭 또는 하위 메뉴에서 Enter는 `workspace::UseClassicLayout`으로 연결되어 `dock_open = true`, `dock_width = None`으로 되돌린다. 다른 pane·sidebar·탭 배치는 변경하지 않는다.
- 기본 폭: `src/ui/metrics.rs::DOCK_DEFAULT_WIDTH = rems_from_px(240.)`. rem 16 기준 240px이다. `effective_dock_width`가 현재 창의 rem으로 변환하고 본문 폭 한계에 맞춰 제한한다. 따라서 창이 매우 좁아 실제 폭이 제한되면 복원 후에도 Custom으로 판정될 수 있다.
- 미구현 Keymap·Themes·Icon Themes·Extensions는 계속 비활성이다. Settings 및 Panel Layout만 동작으로 전환했다.

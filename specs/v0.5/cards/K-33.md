# K-33 — 탭이 넘칠 때 가로 스크롤(I-16)
Zed 기준: `specs/v0.5/SPEC.md` R-16 "Zed 확인(tauri, 2026-11-07)" 표(근거 `cards/C-36.report.md`). 현황: `K-31.report.md`(탭 줄 `layout.rs:314` 줄어들지 않는 h_flex, `tab_bar` 435~).
1. 탭 줄(`tab_list`의 row)만 가로 스크롤 컨테이너로(gpui `overflow_x_scroll` + `ScrollHandle`, pane마다 핸들 유지). 뒤로/앞으로 버튼과 오른쪽 버튼 묶음은 고정. 탭은 원래 폭 그대로, 넘친 쪽은 잘림 — 페이드·화살표·스크롤바 없음(Zed `pane.rs:3653-3665`).
2. 세로 휠 한 칸 = 가로 약 80px(tauri Zed 캡처 값). 상수로 두고 주석에 "Zed capture, toml ID `tab_bar.scroll.wheel_step`(writer W-42가 올림)". gpui가 세로 휠을 가로로 바꿔 주지 않으면 탭 줄의 `on_scroll_wheel`에서 바꾼다. 가로 휠·터치패드 가로 이동도 그대로 동작.
3. 활성 탭이 바뀌면(키보드 `Ctrl-PageUp/Down`, 탭 열기, 클릭) 그 탭이 보이게 스크롤(`scroll_to_item`, Zed `pane.rs:1523`). 사용자가 휠로 직접 스크롤한 뒤에는 활성 탭이 바뀌기 전까지 되돌리지 않는다(Zed `suppress_scroll`).
4. 새 탭은 이미 활성 탭 바로 오른쪽에 들어간다(`pane.rs:331` `place`) — 바꾸지 말고 보고에 확인만.
5. 핀 탭이 있을 때 스크롤되면 핀 탭 오른쪽 경계선(Zed `pane.rs:3720-3728`)은 지금 핀 탭 그리기를 보고 작게 맞출 수 있으면 하고, 크면 보고에 적고 생략.
6. 드래그 앤 드롭·끝 빈 자리(`flex_1` 드롭 자리)·탭 툴팁(K-32)이 그대로 동작해야 한다.
7. 테스트: 활성 탭 보이기 계산(또는 suppress 상태 전이)을 순수 함수로 뺄 수 있으면 그 테스트. 레이아웃 덤프 probe 이름(`tab`, `tab-label-0x`)은 유지.

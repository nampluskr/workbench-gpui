## 1. 수정 내용 상세

### 1.1 Step 3 포커스 상태 가드 (`Get-CurrentFocus`)
- **원인 분석**:
  - `measure-ORDER-10-run1-step3/app-stdout.txt` 685행에서 셋업(두 번째 폴더 추가) 완료 직후 이미 `[dev] focus-state focus=sidebar active=true` 상태였음.
  - 기존 스크립트가 무조건 `Ctrl-Alt-;`(`multi_workspace::FocusWorkspaceSidebar`)를 전송하여, `src/ui/folders.rs:689`의 토글 로직(`if self.sidebar_open && self.sidebar_focus.is_focused(window) { self.return_from_sidebar(...) }`)에 의해 포커스가 `center`로 반환됨.
  - 이로 인해 후속 `Down` 키가 `context=Root > Workspace > Pane`(`action=none`)으로 전달되어 사이드바 선택 테두리가 생성되지 않음.
- **수정 구현**:
  1. `Get-CurrentFocus([string]$outDir)` 헬퍼 함수 추가: `app-stdout.txt` 역방향 스캔으로 최신 `[dev] focus-state focus=(\S+)` 값을 획득.
  2. 키 전송 전 현재 포커스가 `sidebar`인지 확인:
     - 이미 `sidebar`이면 `Ctrl-Alt-;` 전송을 건너뛰어(`Skipping Ctrl-Alt-; to prevent toggling focus away`) 사이드바 포커스를 유지.
     - `sidebar`가 아닐 때만 `Ctrl-Alt-;`를 전송하고, 2초 내 `focus=sidebar` 갱신 여부를 검증(미도달 시 FAIL).
  3. `Down` 키(`0x28`) 전송 후, `app-stdout.txt`에 `key keystroke=down ... Sidebar` 또는 `action-handled name=menu::SelectNext`가 기록되었는지 검증(미도달 시 FAIL).

### 1.2 Step 3 선택 줄 테두리 측정 좌표 덤프 동적 산출
- **수정 구현**:

    $$\text{targetCenterY} = \left\lfloor y + \frac{h}{2} + 0.5 \right\rfloor \quad (\text{덤프 기준 } y=64, h=31 \rightarrow \text{targetCenterY}=80)$$

  - 만약 첫 번째 Down으로 0번 행이 선택된 경우(`zed-sb-down.png` 일치)에도 `folder-row-00` 중앙을 보조 검사하여 진단 정보를 남기도록 방어 로직 추가.

# K-42A — 구문 강조 기반: 의존성(Rust·JSON·Markdown 먼저), 쿼리 복사 스크립트, 로더
네 계획(`specs/v0.5/cards/K-41.report.md`)의 방향을 승인한다: gpui-component의 `tree-sitter` feature는 켜지 않고, Zed와 같은 core·문법으로 기존 `InputHighlighter` API에 연결. 이 카드는 그 기반만 한다(에디터에 색을 칠하는 연결은 K-42B).
**의존성(core D-18 범위, Zed `Cargo.lock`과 같게)**: 이번 카드에서는 `tree-sitter`(core, git `803c6ebaac27d69e1808b45058482e868d073ceb`), `tree-sitter-language`(`[patch.crates-io]`로 같은 git rev, Zed `Cargo.toml` 1039–1042와 같게), `tree-sitter-rust =0.24.2`, `tree-sitter-json =0.24.8`, `tree-sitter-md`(git `b596e737286780d7bfa9fcddceaeeb754574b352`)만 넣는다. 나머지 문법은 K-43에서. `Cargo.lock`의 새 항목 checksum/rev가 K-41 표와 같은지 확인해 보고에 표로.
- `streaming-iterator`: 새 직접 의존성을 넣지 말고 `tree_sitter`가 다시 내보내는 `StreamingIterator`를 쓴다. 그게 안 되면 멈추고 보고(leader가 core에 묻는다).
- `toml`은 dev-dependency 그대로. **실행 중 config.toml을 읽지 않는다**: 언어 표(이름·확장자·파일 이름·first_line_pattern·문법 이름·쿼리 폴더)는 SPEC R-15 표(`specs/v0.5/SPEC.md`, W-48이 옮김)를 코드의 정적 표로 둔다(24행, 이번 카드에서는 표 전체를 두되 문법이 연결된 것은 Rust·JSON·JSONC·Markdown·Markdown-Inline만, 나머지는 "문법 없음 → 평문"). 표와 SPEC이 같은지 테스트(행 수 24, 몇 행 대조).
**쿼리 복사본(D-18, D-9 방식)**: `resources/zed-languages/`를 `.gitignore`에 추가. `tools/fetch-zed-languages.ps1`(기존 `tools/fetch-zed-themes.ps1` 방식, 고정 커밋 `4304dec732a75505066de5ce2dbbfb2bec369498`, 문법 crates/grammars/src/<폴더>/의 highlights·injections·outline.scm, HTML은 extensions/html/languages/html/) — 24개 폴더 전부 복사(K-41 표의 H/I/O), `manifest.json`에 커밋·파일 해시. 스크립트는 레포 밖 Zed 사본이 아니라 GitHub 고정 커밋에서 받아도 되고, 기존 fetch 스크립트가 쓰는 방식을 따른다. **Zed 설치·확장 폴더는 읽지 않는다.** 스크립트를 실제로 한 번 돌려 복사본을 만들고(.gitignore라 커밋 안 됨) 결과 파일 수를 보고.
**로더** `src/ui/syntax.rs`(새 모듈): 앱 시작 때 자기 resource root의 `zed-languages/`에서 쿼리를 한 번 읽어 캐시. 파일이 없으면 그 언어는 평문(앱은 죽지 않음, 경고 한 번). Rust·JSON·Markdown(블록·인라인) 문법으로 `Parser::set_language`와 highlights/injections/outline 쿼리 컴파일이 되는지.
**라이선스**: tree-sitter core·language·rust·json·md를 `resources/licenses/`와 Licenses 창(`src/ui/app_menu.rs` 목록)에 기존 방식대로.

## 사용자 추가 결정 — 가장 안쪽 블록 시작 줄, 열 1

core-leader 추가 결정(사용자 전달): I-5 미리보기 클릭 위치는 누른 곳을 포함하는 가장 안쪽 블록의 원본 시작 줄, 열 1. D-14 확장 범위 안에서 기존 콜백 전달 지점만 조정했다.

- `render_root`의 최상위 전용 래퍼를 `BlockNode::render_block` 및 목록 항목 렌더링으로 옮겼다. 캡처 단계에서 바깥 블록 → 안쪽 블록 순으로 콜백이 오므로 마지막 안쪽 블록의 span이 최종 위치가 된다. 이벤트를 중단하거나 기본 동작을 막지 않는다.
- 앱 콜백은 `status::preview_line_start`로 해당 원본 줄 시작 바이트를 구해 커서에 반영한다. 목록 마커·인용 기호 뒤로 span이 시작해도 열은 1이다. 전체 문서를 다시 파싱하거나 다른 워크스페이스 코드를 복사하지 않았다.

| 블록 종류 | 전달되는 위치 |
|---|---|
| 문단 | 그 문단 span의 원본 시작 줄, 열 1 |
| 제목 | 제목 span의 원본 시작 줄, 열 1 |
| 목록 항목 | 항목 마커 영역은 해당 항목 시작 줄; 내부 문단·중첩 항목은 더 안쪽 블록 시작 줄, 열 1 |
| 코드 블록 | fenced/indented 코드 블록 span의 시작 줄, 열 1. 코드 안에서 누른 개별 행을 계산하지 않음 |
| 표 | 표 span 시작 줄, 열 1. 행·셀은 별도 Markdown 블록으로 취급하지 않음 |
| 인용 안의 블록 | 내부 문단·제목·목록·코드 등 가장 안쪽 블록 시작 줄, 열 1 |
| frontmatter/custom block | 해당 블록 span 시작 줄, 열 1 |
| span 없는 노드·블록 밖 빈 영역 | 해당 노드에서 위치를 새로 전달하지 않음 |

V1 테스트는 두 번째 목록 항목(2행), fenced 코드(4행), 인용 안 문단(10행)의 span 시작 바이트를 줄 시작으로 변환하고 열 1을 확인한다. 실제 AST 렌더 영역과 마우스 캡처 순서는 코드 확인했으며 입력 실행은 V3로 남긴다. 이전 K-23 보고의 최상위 블록 대조 결과는 이 추가 결정 이전의 이력이며 현재 구현은 이 절을 따른다.

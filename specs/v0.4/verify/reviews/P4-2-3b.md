## Must fix

1. **빈 영역 클릭으로 활성 pane과 키보드 포커스가 어긋난다.**
   - 위치: `src/ui/pane_view.rs:210~229`의 capture 및 `activate_pane`, `src/ui/layout.rs:377~385`의 탭 바 빈 영역.
   - 역할: pane 어디든 마우스를 누르면 group.active를 해당 pane으로 바꾼다.
   - 사유: A 편집기에 포커스가 있을 때 B pane의 탭 바 빈 영역을 누르면 capture가 group.active=B로 바꾸지만 해당 영역에는 편집기로 포커스를 옮기는 핸들러가 없다. `activate_pane`도 Window를 받지 않아 실제 포커스는 A에 남는다. 이후 글자 입력은 A에 들어가는데 Ctrl-S·Ctrl-W·분할은 B를 대상으로 한다. 빈 pane 본문도 같은 경로다. 탭 제목 클릭은 `on_tab_press`가 포커스를 옮겨 괜찮지만, 빈 영역은 그 경로를 거치지 않는다.
   - 기대 수정: pane 활성화와 실제 포커스 대상을 일관되게 처리한다. 편집기 본문은 원래 마우스 이벤트·선택·IME 처리를 계속 받게 하면서, 탭 바/빈 본문 클릭은 해당 pane 편집기 또는 빈 pane의 포커스 대상으로 옮긴다. A 포커스 → B 빈 영역 클릭 → 입력·Save/Close 대상이 같다는 최소 회귀 검증을 추가한다(H-9 방식 가능).
   - 미수정 영향: 보고 있는 활성 pane과 입력·저장 대상이 달라져 엉뚱한 파일을 편집하거나 저장한다.

2. **P4-2에 지정된 Pin/Unpin 컨텍스트 메뉴가 없다.**
   - 위치: `src/ui/layout.rs:164~171,252~264`, `src/ui/tab_input.rs` 전체.
   - 역할: 왼쪽 누름·더블클릭·가운데 클릭, 핀 아이콘 및 토글 액션을 연결한다.
   - 사유: TASKS P4-2는 핀/핀 해제 명령을 컨텍스트 메뉴·액션으로 제공하도록 지정한다. 하지만 오른쪽 버튼은 Ignore이고 탭에 메뉴를 여는 핸들러가 없다. 일반 탭을 마우스로 Pin할 경로가 없으며 키 토글만 가능하다. 기존 핀 아이콘의 Unpin은 메뉴를 대신하지 않는다.
   - 기대 수정: 기존 ContextMenu를 재사용해 누른 탭에 Pin/Unpin 명령을 연결한다. 메뉴 항목은 활성 탭이 아니라 실제 대상 pane/탭에 적용되게 하고, 선택·취소 후 포커스 복원도 유지한다. 핀 여부에 따른 항목과 대상을 최소 테스트로 검증한다.
   - 미수정 영향: 카드에 명시한 입력 경로가 미완료다.

3. **Pane/Editor 단축키를 Workspace 전체에 등록해 다른 입력 자리에서도 실행한다.**

   - 역할: Ctrl+K Shift+Enter, Ctrl+백슬래시, Ctrl+K 방향키를 핀/분할 액션에 연결한다.

Ctrl+백슬래시나 Ctrl+K Left도 패널 자리에서 이전 활성 편집기를 분할한다. 코드 주석의 "편집기와 탭 바가 Workspace 안"은 다른 입력 자리까지 포함해도 된다는 원문 근거가 아니다.

## 통과한 연결과 한계

- **핀 닫기 보호:** Ctrl-W·Ctrl-F4는 `on_close_active_item → close_tab_at`, 가운데 클릭은 `tab_press → on_tab_press → close_tab_at`, 탭 닫기 버튼도 같은 함수에 도달한다. `close_tab_at`은 해당 pane의 `close_protected(ix)`를 저장 질문/삭제보다 먼저 검사한다. 가운데 클릭 자체도 pinned이면 Ignore이고, 핀 탭의 끝 슬롯은 닫기 대신 핀 아이콘이다. 폴더·창 종료는 별도 파일 보존 흐름을 유지한다.
- **일반 편집기 클릭:** capture는 model.active를 바꾸고 notify할 뿐 이벤트를 중단하거나 재전송하지 않는다. 원래 편집기 마우스·IME 경로를 직접 덮어쓰지는 않는다. 다만 빈 영역의 포커스 불일치는 1번이며 실제 IME 입력 시뮬레이션은 실행하지 않았다.
- **분할선:** 축 bounds의 시작·길이와 현재 flex로 포인터 delta를 계산해 모델 `drag_divider`에 전달한다. 4px 히트박스·1px 선은 절대 배치여서 flex 공간을 추가 점유하지 않는다. 중첩 최소 크기 계산은 P4-3-R2 모델을 그대로 사용한다. pointer가 제한 밖으로 나갔다 돌아올 때 delta를 누적하지 않는 테스트도 통과했다.
- **Ctrl-K 문자열:** 새 완성 체인은 기존 `ctrl-k ctrl-o`, 프로젝트 패널 `ctrl-k ctrl-shift-c`와 동일 문자열로 중복되지 않는다. Up과 Ctrl-Up도 구별돼 있다. Windows gpui-base Input의 기본 등록에 Ctrl-K 바인딩은 없으며 기존 키 엔진을 재사용한다. 다만 실제 체인 입력의 실행 검증을 했다고 보지는 않으며 새 적용 범위 문제는 3번이다.
- **원문/범위:** preview 제목 기울임·클릭 승격·핀 앞쪽 구간, Split Right/Left/Up/Down 팝업 순서·기본 Clone, 확대 토글과 모델 flex 연결을 코드로 확인했다. 핀 아이콘을 glyph로 근사, split 팝업의 클릭 위치 배치, 분할선 theme.border 근사, 가장자리 이웃 이동의 dock/sidebar 생략은 명시된 shortcut으로 사용자 확인 목록에 유지한다.
- 새 화면의 `focused = group.active == id`는 실제 focus_handle 검사가 아니라 마지막 활성 pane 기준이다. 후속 실측에서 편집기·메뉴·패널로 포커스가 이동한 상태의 I-706 버튼 표시도 확인해야 한다.

## Must fix

1. **세 번째 뷰를 중간 PaneId에 열면 새 편집기가 비어 있는 채 남는다.**
   - 위치: `src/ui/pane_group.rs:629~645` (`open`의 기존 doc 복사 분기).
   - 역할: 다른 pane에 이미 열린 파일이면 새 뷰에 기존 문자열을 복사한다.
   - 사유: `views`는 pane ID 순서지만 복사는 첫 뷰·마지막 뷰만 대상으로 삼는다. pane 0·2에 A가 있고 빈 pane 1에서 A를 열면 목록은 `[기존0, 새1, 기존2]`다. 새1이 first가 아니라는 이유로 last인 기존2에 기존0의 텍스트를 다시 넣으며 새1에는 아무것도 넣지 않는다. Doc은 loaded/clean이어서 새1이 빈 정상 버퍼로 보인다. 새1을 편집하면 그 내용이 기존 뷰로 전파되어 원래 내용까지 사라질 수 있다.
   - 기대 수정: 생성한 편집기 핸들을 정확히 대상으로 잡고, 그 핸들을 제외한 기존 뷰에서 문자열을 가져온다. 첫/마지막 위치로 새 뷰를 추측하지 않는다. pane 0·2가 같은 파일을 보이고 pane 1에 여는 경우를 검증한다(H-9의 순수 대상 선택 함수도 가능).
   - 미수정 영향: 같은 파일의 뷰들이 서로 다른 텍스트를 가지며 공유 dirty·저장 기준이 실제 버퍼를 설명하지 못한다.

2. **읽기 중 이름을 바꾸면 수락된 내용을 현재 뷰에 채우지 못한다.**
   - 위치: `src/ui/pane_group.rs:647~657`, `src/ui/watch_io.rs:260,292`, `src/ui/pane.rs:580`의 rename 경로.
   - 역할: token으로 읽기를 수락한 뒤 경로로 해당 파일의 모든 뷰를 찾아 채운다.
   - 사유: A의 최초 읽기가 시작된 뒤 트리에서 B로 이름을 바꾸면 Docs·Tab 경로는 B가 되지만 token은 유지된다. `finish_read`는 그 token을 찾아 hash·loaded를 갱신한 뒤 Fill을 반환한다. 이어서 캡처해 둔 옛 A 경로로 `fill`하므로 B 뷰는 비어 있는 채 남는다. 감시 reload도 `item.path`가 같은 방식으로 낡을 수 있다. 기존 구현은 수락된 탭의 editor를 직접 받아 채웠으므로 이 호출부 교체가 회귀를 만든다.
   - 기대 수정: 수락한 token이 가리키는 현재 Doc 식별자/경로와 채울 뷰를 함께 해결한다. 최초 읽기와 reload 모두 현재 경로의 뷰에 적용하거나 명시적으로 무효화 후 다시 읽는다. 읽기 시작 → rename → 완료 순서에서 loaded/hash와 실제 내용이 일치하는지 테스트한다.
   - 미수정 영향: 파일 내용을 못 읽었는데도 편집 가능·clean으로 보이며, 그 상태에서 편집·저장하면 원본의 나머지를 덮어쓸 수 있다.

3. **중첩 축을 하나의 pane처럼 줄여 하위 pane의 최소 크기를 깨뜨린다.**
   - 위치: `src/ui/pane_group.rs:151~177,498~502` (`drag_divider`).
   - 역할: 각 축의 자식 크기를 최소 폭 80/높이 100까지 줄이고 남은 이동량을 다음 형제에 넘긴다(I-726).

## R1

결론: REWORK

What this change does: 새 뷰의 복사 대상을 명시하고, rename 중 읽기를 무효화해 새 경로로 다시 읽으며, 하위 트리의 최소 크기를 계산한다. 동기화 대상·선택 위치 판단을 순수 함수로 추출해 실제 연결에서 사용한다.

- 대상: `git log -1`로 확인한 `work/editor` 최신 커밋 `a00a23dc24d6908c2011e557b8d88b01c370a9d6`, `git diff ba2c2f6..a00a23d`. `.worktrees\editor` 검증 전후 HEAD 동일, 수정 없음. 앞선 1~4번(4번은 기존 Should fix)의 수정만 검토했다.
- **1 해소:** `pane_group.rs:642~655`는 방금 배치한 `panes[pane].tabs[o.ix].editor`를 복사 대상으로 고정하고, `copy_source`가 그 핸들을 제외한 기존 뷰를 고른다. pane 0·2 사이의 pane 1에 여는 추가 테스트가 이 실제 선택 함수를 검증한다.
- **2 해소:** `Docs::rename_path`는 해당 doc의 진행 중 읽기 token을 무효화하고 새 경로를 반환한다. `panel_ops::apply_move`는 이를 reload 큐에 넣으며, watcher의 `apply_ready`도 rename 재읽기 대상을 `request_reload`에 포함한다. 또한 Fill 결과가 현재 doc 경로를 포함하고 최초 읽기·watch reload 모두 그 경로로 뷰를 채운다. 추가 테스트는 옛 token 버림·read-only 유지·새 읽기의 현재 경로 Fill 및 관계없는 token 보존을 확인한다. 실제 watcher 타이밍은 실행하지 않았다.
- **4 해소:** `copy_source`·`sync_targets`·`shift`가 실제 `open`·`edited`·`sync_view`에서 사용된다. 단일 뷰 편집, 다른 뷰 일부만 뒤처진 경우, 전부 같은 echo일 때 상태 갱신 생략 및 splice 뒤 선택 위치를 순수 함수 테스트로 확인했다(H-9).

### 남은 Must fix 3

3. **하위 축이 이미 불균등하면 바깥 드래그가 여전히 pane 최소 크기를 깨뜨린다.**
   - 위치: `src/ui/pane_group.rs:275~284,511~515` (`Node::min_len`, `PaneGroup::drag_divider`)와 `Node::rects`의 비율 유지.
   - 사유: 같은 방향 하위 축의 최소값을 자식 최소값의 합으로 구하지만 현재 flex 비율은 반영하지 않으며, 바깥 드래그 뒤 하위 flex도 보정하지 않는다. 따라서 합계만 확보해도 개별 pane이 최소값을 지킨다는 보장이 없다.

# P3-3 리뷰

결론: REWORK

What this change does: 탭 닫기·창 닫기·종료에 저장 질문을 연결하고, 외부 변경·삭제를 저장 전에 확인한다.

- 대상: `work/ui`의 `ca5afb4`, `git diff 646c513..ca5afb4`. H-17 기준으로 ponytail-review와 별도 정확성 리뷰를 수행했다.
- 검증 worktree HEAD는 후속 커밋 `b6526ee`였다. 대상 이후 변경은 `layout.rs`·`metrics.rs`·`mod.rs`의 P3-4b 표시 변경이며 아래 저장·닫기 로직은 동일하다. 테스트를 대상 커밋 자체에서 실행했다고 보지는 않는다.

## Must fix

1. **저장 성공 뒤 새 편집이 남아 있어도 닫힌다.**
   - 위치: `src/ui/tab_close.rs:283,293,298,386` (`save_tab`, `settle`, `request_exit`).
   - 사유: 저장할 B를 캡처한 뒤 백그라운드 쓰기 중 C를 편집하면 `finish_save`는 dirty를 유지하지만, `save_tab`은 I/O 성공만으로 `End::Saved`를 반환한다. 닫기 흐름은 이를 허용해 C를 버린다. 여러 dirty 탭 종료에서도 이미 저장한 첫 탭을 다음 탭 저장 중 다시 편집하거나 새 dirty 탭을 만들면 마지막에 재검사하지 않는다.
   - 기대 수정: 실제 닫기 시점에 현재 버퍼가 저장한 버전인지 확인하고, 종료 대상의 새 편집·새 dirty 탭도 다시 처리한다. 저장 성공과 안전하게 닫을 수 있다는 결과를 구별한다. 저장 도중 재편집 및 여러 탭 처리 중 앞 탭 재편집을 잡는 최소 상태 테스트를 추가한다(H-9).
   - 영향: 사용자가 방금 입력한 내용을 저장 질문 없이 잃는다.

2. **저장 중 dirty가 false가 되면 완료를 기다리지 않고 닫힌다.**
   - 위치: `src/ui/tab_close.rs:336,369,386` (`close_tab_at`, `dirty_tabs`, `request_exit`).
   - 사유: A에서 B로 편집해 저장 중 undo로 A가 되면, 저장 작업은 B를 쓰는 동안 dirty=false일 수 있다. 탭 닫기의 clean 빠른 경로와 종료 대상 필터는 saving 상태를 보지 않는다. 탭이 즉시 사라지거나 종료하여 사용자가 보고 있던 A와 저장되는 B의 차이를 처리할 기회를 없앤다.
   - 기대 수정: clean 빠른 경로보다 먼저 진행 중 저장을 확인하고, 저장 결과와 현재 버퍼를 다시 판정한 뒤 닫는다. 기존 저장을 시작한 뒤 undo·닫기/종료하는 순서를 테스트한다.
   - 영향: 진행 중 쓰기와 닫기가 분리되어 최신 버퍼·저장 결과의 보존을 보장하지 못한다.

3. **저장 전 충돌 검사도 원본 바이트 기준과 맞춰야 한다.**
   - 위치: `src/ui/tab_close.rs:60,191,205` (`guard`, `probe`, 저장 기준 hash 캡처).
   - 사유: `probe`는 LF로 정규화한 문자열 hash를 비교한다. dirty 파일의 외부 인코딩·BOM·줄 끝만 바뀌면 같은 텍스트로 판단해 E-084 확인 없이 이전 format으로 덮어쓴다. H-18은 이런 변경을 원본 바이트 hash로 판정하도록 정했다.
   - 기대 수정: P3-4a-R1의 원본 바이트 기준을 저장 전 검사에도 연결한다. UTF-8→UTF-16/BOM 또는 LF→CRLF 외부 변경은 확인 대상으로, 정확히 같은 바이트 재쓰기는 H-18에 따라 동일 상태로 테스트한다. 감시와 저장 전 검사에 서로 다른 기준을 남기지 않는다.
   - 영향: 외부 프로그램의 파일 형식 변경을 확인 없이 되돌린다.

## 통과 경로와 범위

- 일반 저장 실패·인코딩 거부·사용자 취소는 `End::Cancelled`로 닫기를 중단한다. 저장 확인창의 기본 선택 및 표시 실패는 Cancel이다.

- 기존 저장/대화상자·키맵 구조를 재사용하며, 불필요한 새 의존성은 없다. 다만 단순 성공 enum 테스트로는 위 비동기 상태 경합을 검증하지 못한다.

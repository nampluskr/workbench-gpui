## 회귀·임시 expect 확인

- `src/ui/pane.rs:309`는 새 탭을 활성 탭 뒤에 넣되 핀 구간 안에는 넣지 않는다. 기존 임시 탭을 교체할 때는 활성 위치와 관계없이 임시 탭 인덱스를 재사용한다.
- 탭 이동은 Tab 자체를 옮기므로 editor·읽기/저장 token·dirty 상태를 보존한다. 편집 구독은 editor로 현재 인덱스를 다시 찾으며, 비동기 읽기/저장은 token으로 탭을 찾으므로 pin에 따른 인덱스 변경과 충돌하지 않는다.
- 교체된 임시 탭의 늦은 읽기 버림, 편집 시 일반 탭 승격, 기존 닫기 시 활성 인덱스 보정 테스트도 통과했다. src의 비테스트 탭 삽입·삭제는 해당 모델 경로를 사용한다.
- `pane.rs:444,450,464,480`의 **4개** `cfg_attr(not(test), expect(dead_code, reason=...))`는 각각 `is_pinned`, `close_protected`, `toggle_pin`, `move_tab`에 있다. 모두 사유에 P4-2의 pin key·tab bar·Ctrl-W guard 연결을 명시한다. 테스트에서는 억제하지 않으며 실제 테스트가 이 함수들을 사용한다. P4-2 연결 시 제거해야 하는 한시적 항목으로 확인했고 일반 경고 은폐로 확대하지 않는다.
- 기존 Pane·Tab·preview·이동 인덱스 보정을 재사용하며 별도 타입 계층이나 의존성을 추가하지 않았다. P4-2 연결 전 사용자가 실제로 핀을 조작하거나 닫기 보호를 받는다고 보고하지 않는다.

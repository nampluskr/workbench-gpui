## Must fix

1. **다시 보낸 누름의 Alt+Shift가 창의 현재 수정키 상태에 남는다.**
   - 위치: `src/ui/pane.rs:80–85`의 deferred `window.dispatch_event(PlatformInput::MouseDown(press), cx)`.
   - 역할: 실제 Ctrl+Shift 누름을 Alt+Shift로 바꿔 기존 편집기의 열 선택 시작 로직에 전달한다.
   - 문제: gpui-pre의 `Window::dispatch_event`는 MouseDown을 받으면 `self.modifiers = mouse_down.modifiers`로 창 상태를 덮는다(`gpui-pre-0.3.10/src/window.rs:5664–5667`). 현재 콜백은 재전송 이후 실제 수정키를 복원하지 않는다. 따라서 Ctrl+Shift를 누른 채 포인터를 정지하면 실제로 누르지 않은 Alt가 `window.modifiers()`에 남고 Ctrl은 사라진다. 다음 MouseMove/MouseUp/ModifiersChanged가 와야 우연히 실제 상태로 돌아온다. gpui-base도 이 상태로 커서를 결정하므로(`input/base/state.rs:5115`), 재전송 뒤 정지 상태에서는 Alt용 crosshair가 적용되고 포인터 이동 시 실제 수정키로 돌아가는 등 상태가 일치하지 않는다.
   - 기대 수정: 재전송 전 실제 수정키 상태를 보존하고 재전송 직후 창 상태를 복원하거나, 창 전체 수정키를 바꾸지 않는 범위의 입력 어댑터를 사용한다. 열 선택은 MouseDown 때 저장된 `column_select_start`로 이어지므로 드래그 내내 가짜 Alt를 유지할 필요는 없다(`state.rs:3969–4020`). 복원 이벤트가 선택을 지우거나 다른 입력으로 재해석되지 않는지도 확인한다.
   - 기대 검증: 실제 Ctrl+Shift → 재전송 → 다음 플랫폼 이벤트가 아직 없는 시점에 원래 수정키가 유지되는 회귀 검증을 추가한다. 현재 테스트는 복제된 이벤트의 필드만 검사하므로 창 상태 오염을 잡지 못한다. GPUI test-support를 추가할 수 없다면 lead의 기존 H-9 방식처럼 dispatch/복원 순서를 테스트 가능한 결정으로 분리하고 실제 실행 연결을 코드로 확인한다. 의존성은 승인 없이 바꾸지 않는다.
   - 미수정 영향: 열 선택을 위한 변환이 창 공통 입력 상태까지 바꾸며, 요청된 수정키 잔류 방지 조건을 충족하지 못한다.

## 그 밖의 확인

- 변환 함수는 Ctrl+Shift+왼쪽만 받고 Alt·platform 조합을 제외한다. 일반 클릭·Shift 클릭·Ctrl 클릭·Alt+Shift·오른쪽 버튼은 원본 경로를 통과한다. 복제는 position·button·click_count·first_mouse를 유지한다. Alt가 켜진 재전송은 다시 변환되지 않아 무한 재전송은 없다.
- defer는 GPUI가 dispatch 중 listener 목록을 잠시 꺼내는 구조를 피한다. gpui-base의 열 선택 시작은 MouseDown의 Alt+Shift로 결정되고, 드래그 확장은 저장된 열 시작점으로 진행하며 MouseUp에서 해제한다. 다만 이번 테스트는 실제 선택 영역·IME 조합·포커스의 입력 시뮬레이션까지 검증하지는 않는다. IME 데이터나 텍스트를 직접 수정하는 코드는 추가하지 않았다.
- wrapper div에는 별도 focus handle·키 바인딩·탭 순서가 없다. 기존 Editor의 readonly·h_full을 유지하며 wrapper도 size_full이다. 코드상 포커스 대상 교체는 없다. 실제 편집기 bounds와 스크롤바 hitbox는 아래 실측 필요 목록에 남긴다.
- 스크롤바는 `EditorScrollbarContext`의 기존 scroll handle·viewport·content·axis를 사용한다. 기본 구현과 같은 범위를 사용하고 track width만 변경하며, 새 스크롤 상태나 의존성을 만들지 않았다. L-308 정확 값 검사도 통과했다.

# DECISIONS — workbench-gpui v0.4

## D-1. v0.3 D-1~D-12를 이어받되, D-9의 "값은 바꾸지 않는다"는 이 버전의 D-3·D-6·D-7 범위에서 풀린다

**선택**

- `specs/v0.3/DECISIONS.md` D-1~D-12(그 안에서 이어받은 v0.1·v0.2 결정 포함)를 v0.4에서도 따른다.
- 예외는 셋이다.
  - v0.3 D-9의 "값은 바꾸지 않는다": P4·P5에서 코드 값을 스펙 값으로 맞춘다(D-3).
  - v0.2 D-18의 "탭은 보기 전용": 탭에서 편집과 저장을 허용한다(D-6).
  - v0.3 R-12의 "동작 불변": 의도한 변경 밖만 대조한다(D-8).
- 그 밖의 지난 결정을 바꿀 때는 사용자 승인 뒤 이 문서에 새 `D-n`으로 적는다. 지난 버전 폴더는 고치지 않는다.

**근거**

- 사용자가 v0.4 범위로 "P4 UI 셸 Zed 일치, P5 에디터 코어 정리, 탭 편집과 저장, PoC 6단계 탭 기능"을 골랐다(2026-11-04). 셋 다 v0.3 D-9·v0.2 D-18을 그대로 두면 할 수 없다.
- 지난 버전 폴더는 읽기만 한다(WORKFLOW 5절, 루트 `AGENTS.md` "지난 버전 폴더 불변").

**배제한 대안**

- **지난 결정을 모두 새로 쓴다** — 바뀌지 않은 결정까지 다시 적으면 무엇이 바뀌었는지 가려진다.

## D-2. 순서는 정리 → 일치 → 기능이다

**선택**

- Phase 1 정리(AUDIT 3·4, `Duration` 하드코딩, clippy 경고) → Phase 2 일치(P4 ∥ P5) → Phase 3 탭 편집과 저장 → Phase 4 PoC 6단계 탭 기능.
- 그 앞에 Phase 0 기준선을 둔다(`PLAN.md`).

**근거**

- 사용자 선택(2026-11-04): "정리 → 일치 → 기능".
- 정리가 앞이면 기능 카드가 clippy `-D warnings`와 하드코딩 0건 상태에서 시작한다. 일치가 기능보다 앞이면 새 탭 화면이 맞춰진 값 위에 올라간다.
- P4와 P5는 서로 다른 소유 범위라 병렬로 할 수 있다(초안 PLAN P5 "P4와 병렬 진행 가능").

**배제한 대안**

- **기능 먼저** — 사용자가 고르지 않았다. 일치 작업이 새 기능 화면까지 다시 건드리게 된다.
- **에디터 우선** — 사용자가 고르지 않았다.

## D-3. P4·P5에서는 코드 값을 `spec/zed-metrics.toml` 값으로 맞추고, 대상은 Phase 2 시작 때 실측한 불일치 목록이다

**선택**

- 맞출 대상은 두 가지다.
  - v0.3 스펙 불일치 목록: `sidebar["default_width"]` 스펙 300·코드 375(v0.3 Q-15), `sidebar["footer.height"]` 스펙 30·코드 31(허용 오차 안, 기록만이었음)
  - Phase 2 시작 때 `measure`가 UI 셸·에디터 영역을 V3로 실측해 찾은 불일치
- 값은 스펙 ID 상수(`src/ui/metrics.rs`)를 고쳐서 맞춘다. 스펙에 없는 값은 `spec`이 먼저 추가한다.
- 허용 오차(논리 px ±1, v0.3 Q-6) 안인 불일치도 스펙 값으로 맞춘다. 허용 오차는 측정 판정에만 쓴다. 예: `footer.height` 31 → 30.

**근거**

- 사용자 선택 "P4 UI 셸 Zed 일치"(2026-11-04).
- 사용자 선택 "허용 오차 안 불일치도 맞춘다"(2026-11-04). 루트 `INTENT.md` "Zed와 같아야 한다". 초안 PLAN P4 작업 범위 "P0-6 기준 실측의 UI 셸 불일치 항목".
- v0.3 Q-15: 데스크톱에서 시작 폭이 약 1.25배로 나오는 것은 기존 버그일 가능성이 크고, 원인은 v0.4 후보로 남겼다.
- 수치의 기준은 toml 하나다(v0.3 D-6).

**배제한 대안**

- **v0.3 P0-6 측정 결과만 쓴다** — Phase 1 정리 뒤 화면이 바뀔 수 있다. Phase 2 시작 때 다시 재는 쪽이 맞다.

## D-4. AUDIT 3·4는 감사의 수정안대로, 이미 있는 알림·백그라운드 패턴을 재사용해 고친다

**선택**

- AUDIT 3: 붙여넣기·복제의 일반 실패를 이미 있는 `notify` 또는 삭제 실패의 집계 알림 패턴으로 사용자에게 알린다. 실패한 cut 항목은 클립보드에 남겨 다시 시도할 수 있게 한다.
- AUDIT 4: 큰 파일 첫 열기(`src/ui/pane.rs`), 트리 열기(`panel_nav.rs`), 복사·이동(`panel_ops.rs`)을 백그라운드로 옮긴다. 패턴은 `watch_io.rs`의 감시 재읽기와 `panel_delete.rs`의 삭제가 쓰는 것이다. 완료 때 대상 workspace·요청이 아직 유효한지 확인하고 반영한다. Editor의 `set_value`는 UI 스레드에 남긴다.
- 작업이 겹칠 때는 마지막 요청만 반영한다.
  - 열기: 같은 탭의 이전 요청 결과는 버리고 마지막 요청 결과만 반영한다.
  - 복사·이동: 작업마다 독립으로 동시에 돈다.
  - 취소 UI는 만들지 않는다.

**근거**

- 사용자 선택 "둘 다 고친다"(2026-11-04).
- 동시 실행 정책: 사용자 선택 "마지막 요청만 반영"(2026-11-04). 감사가 "사람이 정해야 한다"고 남긴 항목이다.
- `specs/v0.3/AUDIT.md` 3·4의 Fix 항목.
- ponytail 4.1의 "이 저장소에 이미 있는가"(루트 `AGENTS.md`).

**배제한 대안**

- **새 작업 큐·진행 표시 UI를 만든다** — 감사가 요구하지 않았고 Zed 실측 근거도 없다.
- **진행 중이면 새 요청을 무시한다** — 사용자가 고르지 않았다.
- **취소 기능을 더한다** — Zed 근거가 없어 새 UI 수치를 정해야 한다. 사용자가 고르지 않았다.

## D-5. 남은 `Duration` 하드코딩과 clippy 경고 10개를 0건으로 만들고, 이후 clippy는 `-D warnings`로 막는다

**선택**

- AUDIT 6 위치 밖 `Duration::from_*`(watch·keymap·dev·editor_poc·watch_io·mod)를 스펙 ID 상수로 옮긴다. 값은 바꾸지 않는다.
- Zed 원문에 없는 앱 자체 시간 값(감시 디바운스 등)은 지금 방식대로 `src/ui/metrics.rs`에 `// spec: none (app value)` 주석과 함께 둔다(예: `FOLDERS_SAVE_DEBOUNCE`, `SHORTCUT_FLASH`). toml은 Zed 실측만 담는다.
- clippy 기준선 경고 10개를 고친다. 고친 뒤에는 `cargo clippy --all-targets -- -D warnings`가 통과해야 완료다. 루트 `AGENTS.md` 2장의 "Phase 0 기준선의 clippy 경고는 기록만" 예외는 Phase 1 뒤 없앤다.

**근거**

- 사용자 선택 "Duration 하드코딩, clippy 경고 10개"(2026-11-04).
- 앱 자체 값의 자리: 사용자 선택 "metrics.rs 앱 상수"(2026-11-04).
- v0.3 PROGRESS "남은 것" 3·4.

**배제한 대안**

- **`#[allow]`로 경고를 숨긴다** — 루트 `AGENTS.md` 5장 금지.
- **toml에 앱 섹션을 둔다** — 기존 앱 상수까지 옮겨야 한다. 사용자가 고르지 않았다.

## D-6. 탭은 편집할 수 있게 하고, 저장·저장 질문·충돌 표시·지워진 파일 표시·저장 확인창을 Zed 규칙대로 더한다

**선택**

- v0.2 D-18(보기 전용)을 바꿔 탭에서 편집을 허용한다.
- 함께 들이는 Zed 규칙은 v0.2 D-18이 미룬 목록이다.
  - 저장과 저장 질문(A-13.4, I-069)
  - 디스크 변경 충돌 표시(E-086 의 수정한 버퍼, 탭 점 Warning 색, G-115)
  - 지워진 파일 탭 표시(E-087)
  - 저장 때 확인창(E-084, E-085)
- 깨끗한 버퍼 자동 다시 읽기(E-086 앞부분)는 v0.2 동작 그대로다.
- 편집기는 지금 탭(`src/ui/pane.rs`)이 쓰는 gpui-kit Editor를 그대로 쓰고 편집 막음만 푼다. 에디터를 직접 만들지 않는다.
  - `src/ui/editor_poc.rs`는 gpui-kit Editor를 띄워 재는 디버그 전용 측정 화면이다(v0.1 Phase 2). 탭 편집의 기반이 아니다.
  - Zed와 다른 점은 이 Editor 위에 더한다(D-10).
- 저장은 열 때의 인코딩·BOM·줄 끝을 그대로 지킨다. 이미 있는 `TextEncoding`·`RoundtripMode`(`src/`)를 기준으로 한다.
  - LF·CRLF UTF-8 보존은 gpui-kit으로 된다(v0.1 POC-TABLE).
  - 직접 구현 3건을 v0.4에 넣는다: UTF-16 LE 열기·저장, CP949 열기·저장, CP949로 옮길 수 없는 글자의 저장 손실 막기(best-fit 금지, 저장을 막고 알린다). v0.1 POC-TABLE R-11 요약 9~11번이다.

**근거**

- 사용자 선택 "탭 편집과 저장"(2026-11-04).
- 편집기: 사용자 선택 "gpui-kit Editor 유지"(2026-11-04). v0.1 POC-TABLE: IME·다중 커서·10만 줄·LF/CRLF 보존은 gpui-kit 지원.
- 인코딩: 사용자 선택 "원래 인코딩 보존 + 3건 포함"(2026-11-04).
- v0.2 D-18 "저장 기능과 함께 이후 버전에서 다룬다", v0.2 PROGRESS "남은 것" 3.

**배제한 대안**

- **편집만 열고 저장 질문·충돌 표시는 뒤로 미룬다** — 저장하지 않은 변경을 잃을 수 있다. 데이터 손실 방지는 줄이지 않는다(루트 `AGENTS.md` 4.3).
- **에디터를 직접 구현한다** — IME·대용량까지 다시 만들어야 해 범위가 크게 는다. 사용자가 고르지 않았다.
- **UTF-8만 편집하거나 모두 UTF-8로 저장한다** — 앞은 다른 인코딩 파일을 편집할 수 없고, 뒤는 원본 인코딩을 바꾼다. 사용자가 고르지 않았다.

## D-7. PoC 6단계 탭 기능은 미리보기 탭·핀·분할·탭 드래그·마크다운 미리보기이고, 규칙은 01-zed 02-INTERACTION 2·3절이다

**선택**

- 범위: 미리보기(preview) 탭, 핀 탭, 분할, 탭 드래그, 마크다운 미리보기(v0.2 PROGRESS "남은 것" 3의 PoC 6단계).
- 규칙의 원문: 02-INTERACTION 2절(`I-060~I-066` 미리보기·핀), 3절(`I-067~I-076` 탭 동작), 01-LAYOUT 4.4(탭 바 `L-22~L-27`, `L-61~L-74`, `L-300`). 수치는 `spec`이 먼저 toml에 옮긴다.
- 분할은 02-INTERACTION 3.1(`I-706~I-739`)을 모두 따른다: 상하좌우 4방향, 개수 제한 없음, 분할 방식 3가지(`ClonePane` 기본·`EmptyPane`·`MovePane`), 탭을 끌어 본문 가장자리에 놓아 분할하는 드롭 영역.
- 마크다운 미리보기는 설치된 gpui-component 0.8.1의 마크다운 렌더(text 모듈)를 쓰고, 스타일을 01-LAYOUT 5절(`L-101~`) 값에 맞춘다. 탭 규칙은 `L-69`(제목 "Preview {파일명}"), 미리보기 버튼은 `E-039`다. 렌더가 맞추지 못하는 값은 V3 불일치 목록에 남긴다. 새 의존성은 더하지 않는다.
- 탭·분할 상태 복원(`I-112~I-120`)은 PoC 8단계라 넣지 않는다(`INTENT.md` 제외 범위).

**근거**

- 사용자 선택 "PoC 6단계 탭 기능"(2026-11-04, 선택지 설명 "미리보기 탭·핀·분할·탭 드래그, 마크다운 미리보기").
- 분할: 사용자 선택 "Zed 원문 전부"(2026-11-04).
- 마크다운: 사용자 선택 "gpui-component 렌더 + Zed 스타일"(2026-11-04).
- `spec/INDEX.md`의 탭 관련 절 위치.

**배제한 대안**

- **PoC 6단계 가운데 일부만 한다** — 사용자가 단계 단위로 골랐다. 줄이려면 사용자가 정한다.
- **분할을 좌우만, 또는 명령으로만 한다** — 사용자가 고르지 않았다.
- **마크다운을 직접 렌더한다** — 코드가 많고 의존성 승인이 필요할 수 있다. 사용자가 고르지 않았다.

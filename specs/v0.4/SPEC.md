## 공통 판정 방식

- **회귀 대조가 모든 요구의 전제다.** 어떤 변경도 R-15(의도한 변경 밖은 기준선과 같다)를 깨면 그 요구는 충족되지 않은 것이다.
- **검증 수준:** 작업마다 D-8의 검증 수준(V0~V4)을 정하고 PROGRESS에 적는다. R-15의 Phase 끝 재실행은 수준과 관계없이 항상 한다.
- **수치:** 기대값은 `spec/zed-metrics.toml`의 스펙 ID로 적는다. 스펙에 없는 값은 `spec`이 먼저 추가한다(R-2).

- **증거 위치:** `specs/v0.4/verify/` 아래 `reviews/`(리뷰·실측), `baseline/`(기준선·Phase별 재실행).

## R-4. 큰 파일 첫 열기와 복사·이동이 UI 스레드를 막지 않는다

**요구**

AUDIT 4를 고친다. 파일 전체 읽기, 재귀 복사, 교차 볼륨 이동을 백그라운드에서 하고, 완료 때 대상이 아직 유효한지 확인한 뒤 반영한다.

**정해진 결과**

- `pane.rs`·`panel_nav.rs`·`panel_ops.rs`의 해당 경로가 UI 스레드에서 파일 IO를 하지 않는다.
- 완료 전에 workspace·탭이 닫히면 결과를 버린다.
- 같은 탭에 열기 요청이 겹치면 마지막 요청 결과만 반영된다. 복사·이동은 서로 독립으로 동시에 돈다. 취소 UI는 없다.

**판정 방법**

- 코드 확인: 해당 핸들러에 동기 파일 IO가 없다.
- 무효가 된 요청의 결과를 버리는 테스트와, 겹친 열기에서 마지막 요청만 반영되는 테스트(V1)가 있고 통과한다.

**출처**

D-4 · `specs/v0.3/AUDIT.md` 4

## R-10. 저장할 수 있고, 저장하지 않은 변경을 잃지 않는다

**요구**

저장과 저장 질문, 저장 때 확인창을 Zed 규칙대로 만든다(A-13.4, I-069, E-084, E-085).

**정해진 결과**

- 저장 명령으로 디스크 파일이 버퍼 내용과 같아지고 수정 표시가 사라진다.
- 수정한 탭이나 창을 닫으면 저장 질문이 뜨고, 답에 따라 저장·버림·취소된다.
- 확인창 조건은 E-084·E-085를 따른다.
- 저장한 파일의 인코딩·BOM·줄 끝이 열 때와 같다. UTF-8(LF·CRLF), UTF-16 LE, CP949를 열고 저장할 수 있다.
- CP949로 옮길 수 없는 글자가 있으면 저장하지 않고 알린다(best-fit 변환 금지).

**판정 방법**

- 저장 결과와 저장 질문 분기 테스트(V1)
- 인코딩별 왕복(열기 → 저장 → 바이트 비교) 테스트와 CP949 손실 거부 테스트(V1)
- 저장 질문 화면 첫 구현 V3

**출처**

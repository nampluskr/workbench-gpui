# PLAN — workbench-gpui v0.4

## 읽는 법과 이 순서에 걸린 규칙

**번호와 이름**
- `R-n`은 v0.4 `SPEC.md`, `D-n`은 v0.4 `DECISIONS.md`의 번호다. 지난 버전 번호는 `v0.3 R-n`처럼 쓴다.
- 카드 ID는 `P<Phase>-<번호>`(예: P1-2)다. rework 카드는 `-R1`, `-R2`를 붙인다.
- 담당 이름과 모델은 `HERDR-SETUP.md` 1장, 검증 수준 `V0~V4`는 루트 `AGENTS.md` 3A.1을 따른다.

**순서의 이유**(D-2, 사용자 선택 2026-11-04 "정리 → 일치 → 기능")
- Phase 0이 맨 앞인 이유: v0.4는 동작을 바꾼다. 바꾸기 전 상태를 기준선으로 잡아야 의도한 변경과 회귀를 가릴 수 있다(R-15). 새 화면 수치도 구현 전에 스펙에 있어야 한다(R-2).
- Phase 1(정리)이 일치·기능보다 앞이다. 이후 카드가 clippy `-D warnings`와 하드코딩 0건 상태에서 시작한다.
- Phase 2(일치)가 기능보다 앞이다. 새 탭 화면이 맞춰진 값 위에 올라간다.
- Phase 3(탭 편집·저장)이 Phase 4(탭 기능)보다 앞이다. 미리보기 탭 승격과 분할이 수정한 버퍼를 다루므로 저장 질문·충돌 표시가 먼저 있어야 한다.

**Phase 진행 규칙**
- Phase는 순서대로 진행한다. 이전 Phase의 완료 조건을 통과해야 다음 Phase를 시작한다.
- Phase 2의 P4(`impl-ui`)와 P5(`impl-editor`)는 병렬로 진행할 수 있다.
- v0.4 미결 사항은 2026-11-04에 모두 정했다(`DECISIONS.md`). 진행 중 새 미결이 생기면 그 Phase 착수 전에 사용자에게 받는다.
- 계획 변경은 `lead`가 사용자에게 보고하고, 승인 후 이 문서를 고친다.

**Phase 시작 때 (`lead`)**
1. 이 문서의 해당 Phase 절을 기준으로 작업 카드를 `TASKS.md`에 쓴다. 카드마다 검증 수준(기본 V0)과 리뷰어(동작 변경은 `reviewer`, 값 맞춤·정리는 `review`)를 지정한다.
2. 카드 목록을 사용자에게 보고하고, 승인 후 지시를 시작한다.

**Phase 종료 때 (`lead`)**
1. v0.2 검증 스크립트 9개를 다시 돌려 R-1 기준선과 대조한다(R-15, `measure` 실행, `reviewer` 판정). Phase 0은 기준선을 만드는 Phase라 제외한다.
2. 바뀐 화면과 쌓인 "실측 필요" 항목을 묶어 V3 카드를 만든다(`measure`). 불일치는 rework 카드로 처리하고 불일치 항목만 다시 잰다.
3. "사용자 확인 필요" 항목을 모아 사용자에게 한 번에 전달한다(V4).
4. `/ponytail-debt`로 `shortcut:` 주석을 점검한다.
5. `reviewer`가 병합 직전 최종 확인(`@ponytail-review`, 전체 테스트 1회)을 한다.
6. `HANDOFF.md`·`PROGRESS.md`를 갱신하고 Phase 단위로 커밋한다. 태그는 `v0.4-phase-<번호>`다.
7. 완료 조건을 채웠는지 사용자에게 보고하고, 승인 후 다음 Phase로 넘어간다.

**모든 작업에 걸리는 규칙**
- 작업을 끝낼 때마다 `PROGRESS.md`에 무엇을·결과·검증(수준 포함)을 적는다. 계획 밖 작업은 사용자 요청 작업으로 적는다.
- 빌드할 때마다 `tools/apply-manifest.ps1`을 다시 실행한다.
- 지난 버전 폴더에는 쓰지 않는다. `tools/verify-v02-*.ps1`은 항상 `-OutDir specs\v0.4\verify\...`로 돌린다.

## Phase 0 — 기준선과 새 화면 스펙

**목적**

v0.4 변경 전 상태를 기준선으로 고정하고, Phase 3·4에 쓸 새 화면 수치를 스펙에 옮긴다. src는 바꾸지 않는다.

**대응**

R-1 · R-2 · D-6 · D-7 · D-8

**완료 조건**

- `specs/v0.4/verify/baseline/`에 9개 스크립트 결과와 build·test·clippy 기록이 있고, v0.3 종료 기록과 같다(R-1).
- `spec/zed-metrics.toml`에 탭 편집·저장·탭 기능 항목(분할 `I-706~I-739`, 마크다운 미리보기 `L-101~` 포함)이 들어 있고, 모호 항목이 `spec/ambiguous.md`에 있으며, `review` 표본 대조가 PASS다(R-2).
- Phase 0 동안 src 변경이 없다.

## Phase 1 — 정리: AUDIT 3·4, `Duration` 하드코딩, clippy

**목적**

v0.3에 남은 동작 위험과 정리 항목을 고친다. AUDIT 3·4는 동작이 바뀌는 카드라 별도 커밋으로 나눈다.

**대응**

R-3 · R-4 · R-5 · R-6 · R-15 · D-4 · D-5

**완료 조건**

- AUDIT 3 부분 실패 테스트가 통과한다(R-3, 리뷰 `reviewer`).
- AUDIT 4 해당 경로에 동기 파일 IO가 없고, 무효 요청 테스트가 통과한다(R-4, 리뷰 `reviewer`).
- `Duration` 하드코딩 grep 0건(R-5, 리뷰 `review`).
- `cargo clippy --all-targets -- -D warnings` exit 0, 새 `allow` 없음(R-6, 리뷰 `review`).
- R-15 대조에서 목록 밖 차이가 없다. 의도한 변경은 AUDIT 3·4의 알림·클립보드·비동기 반영뿐이다.
- 루트 `AGENTS.md` 2장의 clippy 기준선 예외를 없애는 개정을 사용자에게 올렸다.

## Phase 3 — 탭 편집과 저장

**목적**

탭에서 편집을 허용하고, 저장·저장 질문·저장 확인창·충돌 표시·지워진 파일 표시를 Zed 규칙대로 더한다.

**대응**

R-9 · R-10 · R-11 · R-15 · D-6

**완료 조건**

- 편집 입력 테스트와 수정 표시가 통과한다(R-9).
- 저장 결과, 저장 질문 분기(저장·버림·취소), 확인창 조건, 인코딩 왕복(UTF-8·UTF-16 LE·CP949)·CP949 손실 거부 테스트가 통과한다(R-10).
- 충돌·지워진 파일 표시 테스트가 통과하고, 깨끗한 버퍼 자동 다시 읽기가 v0.2와 같다(R-11).
- 새 화면(수정 표시, 저장 질문, 충돌·지워진 표시) V3 불일치 0.
- 카드 리뷰는 모두 `reviewer`다.
- R-15 대조에서 목록 밖 차이가 없다.

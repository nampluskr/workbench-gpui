# SPEC — workbench-gpui v0.3

## 공통 판정 방식

- **동작 불변이 모든 요구의 전제다.** Phase 1~3의 어떤 변경도 R-12(동작 불변)를 깨면 그 요구는 충족되지 않은 것이다.
- **검증 수준:** 작업마다 D-7의 검증 수준(V0~V4)을 정하고 PROGRESS에 적는다. 수준을 넘는 검증은 하지 않는다. R-12의 Phase 끝 전체 재실행은 예외로, 수준과 관계없이 항상 한다.
- **지난 버전 폴더:** `specs/v0.1/`, `specs/v0.2/`에는 쓰지 않는다. `tools/verify-v02-*.ps1`을 돌릴 때는 항상 `-OutDir`로 `specs\v0.3\verify\...` 아래 경로를 넘긴다.
- **증거 위치:** 검증 증거는 `specs/v0.3/verify/` 아래에 둔다.
  - `reviews/`: 기준선, 리뷰, 실측 비교
  - `baseline/`: v0.2 검증 스크립트 기준선
  - `phaseN/`: Phase별 재실행 결과·표본 대조
  - `finalize/`: 의도·결정 검토

## R-1. 데스크톱 빌드 환경이 노트북과 같은 버전이다

**요구**

**정해진 결과**

## R-5. 01-zed 실측 수치가 `spec/zed-metrics.toml`로 옮겨져 있고, 모호·충돌 항목이 따로 정리되어 있다

**요구**

`docs/refs/01-zed/` 네 문서의 수치를 하나의 수치 스펙 파일로 옮긴다. 값이 불분명하거나 원문끼리 충돌하는 항목은 따로 정리한다.

**정해진 결과**

- **`spec/zed-metrics.toml`**
  - 항목마다 `value`·`unit`·`cond`·`src`가 있다.
  - `src`는 원문 파일과 절 위치를 가리키고, 원문 항목 ID(L-n, A-n.n 등)가 있으면 함께 적는다.
  - 측정 조건은 `[conditions.<이름>]`으로 정의되어 있고, 모든 `cond`가 정의된 조건을 가리킨다.
- **`spec/ambiguous.md`:** 값·단위·조건 가운데 하나라도 불분명한 항목과, 원문끼리 값이 다른 항목이 원문 위치와 함께 적혀 있다. 이런 항목은 toml에 없다.
- **`spec/INDEX.md`:** 문서별 한 줄 요약, 절 목록(앵커), 화면 영역, 측정 조건 기재 여부가 있다. 동작 규칙의 절 위치도 여기에 적혀 있다.
- PROGRESS에 항목 수, 모호 항목 수, 충돌 항목 수가 기록되어 있다.

**판정 방법**

- toml을 파서로 읽어 다음을 확인한다. 하나라도 어기면 실패다.
  - 모든 항목에 네 필드가 있다.
  - 모든 `cond`가 정의되어 있다.
  - 중복 ID가 없다.
- 표본 대조 결과는 R-6이 판정한다.

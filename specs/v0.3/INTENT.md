# INTENT — workbench-gpui v0.3

## 목적·범위·기대 결과

- 목적: v0.2까지 만든 코드를 ponytail 기준으로 리팩토링한다. 기능을 더하지 않고 동작도 바꾸지 않는다. 대신 다음 세 가지를 한다.
  - Zed 실측 수치를 한 곳(수치 스펙 파일)에 모은다.
  - 코드의 하드코딩 수치·색상과 중복을 없앤다.
  - 이후 버전이 Zed와 같은지 빠르게 확인할 수 있는 검증 기반을 만든다.
- 범위: `docs/refs/refactor-draft/PLAN.md`의 P0~P3이다(사용자 결정 2026-11-03).
  - Phase 0 기준선: 데스크톱 환경을 노트북과 같게 맞추고, v0.2 동작 기준선을 만든다. ponytail-audit로 저장소를 감사하고, 01-zed 실측 문서를 수치 스펙 파일(`spec/zed-metrics.toml`)로 옮긴다.
  - Phase 1 검증 기반: 스펙 ID로 기대값을 찾는 레이아웃 테스트 틀, 레이아웃 덤프, UI 실측 절차를 만든다.
  - Phase 2 상수·테마 통합: 코드에 흩어진 수치·색상을 스펙 ID 상수와 테마 경유로 옮긴다.
  - Phase 3 공통 컴포넌트: 반복되는 스타일 체인과 비슷한 컴포넌트를 합치고, 쓰지 않는 의존성을 정리한다.
  - 대상은 `src/` 전체와 그에 딸린 테스트·검증 스크립트(`tools/`)다.
- 기대 결과
  - v0.2의 동작이 바뀌지 않았다는 것을 기준선 대조로 보인다.
  - 코드 안의 하드코딩 수치·색상과 중복 컴포넌트가 감사 기준 0건이다.
  - 새 레이아웃 테스트를 스펙 ID만으로 쓸 수 있다.
  - 세부 항목과 판정 방법은 `SPEC.md`가 담는다.

## 배경

v0.2(PoC 4~5단계: 키맵·액션, 폴더 등록·트리·파일 작업·감시)를 마쳤고, 사용자가 종료를 결정했다(2026-11-02, `specs/v0.2/PROGRESS.md` "버전 종료").

다음 버전을 정하면서 사용자가 결정한 것(2026-11-03):
- 원래 v0.3에 하려던 단계는 v0.4에서 한다.
- v0.3에서는 v0.2까지의 작업을 리팩토링한다. 사용자 말: "제일 먼저 github.com/nampluskr/workbench-gpui 에 대한 poytail 기반 리팩토링을 해야 합니다."(`docs/refs/refactor-draft/HERDR-SETUP.md` 1절에 인용됨)
- `docs/refs/refactor-draft/`의 문서는 사용자가 claude.ai에서 미리 검토한 것이다. 참고가 아니라 이 문서를 **기준으로** v0.3를 진행한다. 사용자 말: "참고가 아니라 이 문서를 기준으로 v0.3 이 이루어져야 합니다."
  - 반영 기준은 세 가지다: 데스크톱 환경, 멀티 에이전트의 토큰 부담, 자료·파일 경로.
  - 원문은 보존하고, 고쳐 반영한 문서는 다음과 같다.
    - `specs/v0.3/HERDR-SETUP.md`
    - 루트 `AGENTS.md`
    - `specs/v0.3/PLAN.md`
    - 이 문서와 DECISIONS·SPEC
  - 범위는 초안 PLAN의 P0~P3이다.
  - 들여오는 방식은 네 가지다: 수치 스펙 파일, 검증 수준 V0~V4, 레이아웃 테스트·덤프 도구, 하드코딩 0건 목표.
  - 에이전트는 초안 HERDR.md의 역할을 토큰 부담에 맞게 조정해 쓴다.
  - 결정 내용은 `DECISIONS.md` D-2, D-6~D-12에 있다.

v0.1·v0.2는 노트북에서 작성했다. v0.3은 GitHub에서 클론한 저장소로 데스크톱에서 작업한다. `docs/refs/assets/`의 Zed 스크린샷도 노트북에서 실행한 Zed 화면이다(사용자 2026-11-03). 그래서 리팩토링보다 먼저 다음 세 가지를 한다(사용자 지시 2026-11-03, `PLAN.md` Phase 0).
- 설치 환경을 노트북과 같게 맞춘다.
- v0.2 동작을 점검한다.
- ponytail 설치·사용 여부를 확인한다.

## 제외 범위

- 새 기능. v0.2 "버전 종료"의 남은 것 3에 있는 범위는 전부 v0.4 이후로 간다(사용자 결정 2026-11-03). 그 범위는 다음과 같다.
  - PoC 6~8단계(테마·아이콘 테마 매핑과 선택기 포함)
  - 탭 편집과 저장
  - 프로젝트 패널 드래그 앤 드롭
  - 편집기 직접 구현 12건
  - 패키징·서명
- 초안 PLAN의 P4(UI 셸 정리)·P5(에디터 코어 정리)·P6(신규 기능). 화면을 Zed 실측에 맞추려고 값을 바꾸는 수정이라 동작이 바뀐다. v0.4 이후로 간다(사용자 결정 2026-11-03). v0.3에서 찾은 코드 값과 스펙 값의 불일치는 고치지 않고 목록으로만 남긴다.
- 동작이 바뀌는 수정(감사에서 나온 버그·위험 항목 수정): 리팩토링이 아니다. AUDIT 3(실패 알림)·4(UI 정지)는 v0.4 이후로 간다. 예외로 데이터 손실 위험 AUDIT 1·2는 Phase 3 뒤 별도 카드·별도 커밋으로 v0.3에서 고친다(사용자 결정 2026-11-03, `PLAN.md` "Phase 3 뒤").
- 초안 가운데 워크스페이스 규칙과 맞지 않는 것
  - 지난 PLAN·PROGRESS의 보관 처리(지난 버전 폴더 불변)
  - 루트 `AGENTS.md`를 통째로 바꾸는 것(기존 레포 규칙은 남긴다)
  - 그 밖의 초안 경로는 `specs/v0.3/` 아래로 바꿔 반영한다(D-11).
- 지난 버전 폴더(`specs/v0.1/`, `specs/v0.2/`)의 수정·이동·보관 처리.

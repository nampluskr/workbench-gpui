# SPEC — workbench-gpui v0.2

## 공통 판정 방식

v0.1 SPEC 의 공통 판정 방식과 같다.

- 판정은 wg-checker 가 한다. 결과는 `specs/v0.2/verify/`에 보고서로 남긴다.
- 화면 요구의 증거는 앱 실행 스크린샷(기준 화면과 같은 창 크기·배율, A-30.1·A-30.2)과 측정값(px, hex)이다. 01-zed 항목 ID 별로 기대 값과 나란히 적는다.
- 치수 판정의 기준은 소스 값(L-)이고 허용 오차는 ±1 논리 px 다(A-31.1). 판정은 항목마다 통과/실패로 적는다(A-30.5).
- 키·동작 요구의 증거는 입력(SendInput)과 그 결과(앱의 디버그 전용 dev 플래그 출력, 스크린샷, 파일 시스템 상태)다. 키는 포커스 위치를 같이 적는다(A-33.1, I-002).
- 앱이 내는 문구는 원문 문구와 글자 하나까지 같아야 한다.

## R-2. 사용자 keymap.json 이 내장 키맵 위에 마지막으로 얹히고, null 은 낮은 후보를 해제한다

**요구**

`keymap.json`(A-20.4, Zed 와 같은 객체 배열 형식)을 읽어 내장 키맵 위에 얹는다. 나중 것이 이긴다(A-27.1). 바인딩 값이 `null` 이면 그 컨텍스트에서 낮은 우선순위 후보를 해제한다(I-703).

**정해진 결과**

- `keymap.json` 에 내장 키와 같은 키를 다른 액션으로 묶으면 사용자 쪽 액션이 실행된다.
- `keymap.json` 에 키를 `null` 로 적으면 그 컨텍스트에서 내장 바인딩이 실행되지 않는다.
- 바인딩 값은 우리 앱에 있는 액션 이름만 쓴다. 없는 액션 이름은 읽기 오류로 알린다(A-20.4, A-20 아래 목록 "읽기 오류는 A-45 의 알림으로").
- 파일 위치는 `%APPDATA%\workbench-gpui\keymap.json` 이다(D-11).
- 주석(`//`, `/* */`)과 끝 쉼표를 허용한다(D-4, `jsonc-parser`).

**판정 방법**

시험용 `keymap.json` 네 가지(덮어쓰기, `null` 해제, 없는 액션 이름, 주석·끝 쉼표가 있는 파일)로 앱을 띄워, 해당 키 입력의 결과와 dev 플래그의 바인딩 출력·오류 출력을 확인한다. 읽기 오류 알림은 문구만 판정한다(D-14).

**출처**

D-2 · D-3 · D-4 · D-11 · D-14 · A-20.4 · A-27.1 · I-703 · G-006 · G-020 · G-105

## R-6. 툴팁이 L-206~L-216 의 시점·위치·모양대로 뜨고 사라진다

**요구**

툴팁의 지연·사라짐·위치·모양을 01-zed 값과 맞춘다(D-5).

**정해진 결과**

- 지연 500ms(L-206). 프로젝트 패널 항목은 1500ms(L-206, L-247).
- 마우스가 벗어나거나, 마우스 버튼을 누르거나, 스크롤하면 사라진다(L-207).
- 띄우는 순간의 마우스 위치에서 (+1, +1)px, 투명 여백 왼쪽 8·위 10 이라 보이는 상자는 커서에서 약 (9, 11)px(L-208, L-209). 오른쪽·아래가 창을 넘으면 커서 왼쪽·위쪽으로 뒤집는다(L-210).
- 바탕 `elevation_2`, 모서리 8px, 테두리 1px, 그림자 두 겹(L-211, L-212). 안쪽 여백 위아래 4·좌우 8(L-213). 글자 14px(L-214). 제목 최대 폭 288px(추정)과 단축키 사이 gap 16(L-215). 메타 줄 12px Muted(L-216).
- 메뉴를 여는 버튼은 메뉴가 열려 있는 동안 툴팁이 없다(L-205, L-272).
- 색 토큰 값은 테마 매핑(PoC 7단계) 전이라 판정하지 않는다. 판정 대상은 시점·위치·치수다.

**판정 방법**

SendInput 으로 마우스를 올려 시각을 재고(스크린샷 연속 캡처), 툴팁 상자의 위치·치수를 측정한다. 창 오른쪽·아래 끝 근처에서 뒤집기를 확인한다.

## R-8. ☰ 앱 메뉴가 01-zed 9.1절 방식으로 열리고 02 9.2절 구조를 따른다

**요구**

타이틀 바 ☰ 메뉴를 01-zed 방식으로 만든다(D-5).

**정해진 결과**

- 닫힌 상태에는 `Menu` 아이콘 버튼 하나(Subtle, Small 14)만 보인다(L-85, I-302). 누르면 첫 메뉴(앱 이름)가 열리고, 열려 있는 동안 가로 메뉴 바가 나타난다(I-302, L-86). 메뉴 바에는 v0.2 에 동작하는 항목이 있는 메뉴만 둔다(D-13, I-306).
- 메뉴가 열려 있으면 다른 메뉴 이름에 마우스를 올리는 것만으로 바뀐다(I-303). Left/Right 는 끝에서 반대편으로 순환한다(I-303).
- 하위 메뉴는 없고 묶음 항목은 부모 메뉴에 펴서 넣는다(I-304, A-18.2). 구분선 정리 규칙은 I-306.
- F10 = 열기, 열린 채 F10 = 닫기(I-310). 목록 안 키는 R-9 의 메뉴 키.
- 항목 실행 전에 원래 포커스를 복원한다(I-309).
- `Zed` 가 들어간 문구는 앱 이름으로 바꾼다(A-18.10).
- 메뉴 항목은 02 9.2절·A-18.3~A-18.9 가운데 v0.2 에서 동작하는 것만 둔다(D-13). 문구·순서·구분선은 02 9.2절 그대로다. 이 문서를 쓸 때 기준으로 본 항목은 다음과 같다. 최종 목록은 Phase 2 에서 02 9.2절 원문과 대조해 확정하고 보고서에 적는다.

  - File: Open Folder...(= 폴더 등록, A-13.1), Close Window (A-18.4)
  - View: Toggle Left Dock, Toggle Folder Sidebar, Focus Folder Sidebar, Project Panel (A-18.7)

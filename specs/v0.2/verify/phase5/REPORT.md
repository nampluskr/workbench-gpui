## 4. R-24 트리 반영

판정 12개(tree), 모두 통과. 스크린샷 `tree-after.png`, `flood-created.png` 를 열어 보았다.

- 접힌 폴더 안 변경(`src\added.rs`)도 이벤트를 받아 펼치면 보인다.
- 600개 만들기: 트리 행 수 600 = 디스크 파일 수, 반영 6번(이벤트 1405개), 지우기 후 `flood` 아래 0개. `flood-created.png`: `flood` 가 펼쳐져 `fl-0000.txt`…`fl-0025.txt` 순서대로 보인다(첫 화면만 열었다).

## 7. 감시자 수명(switch)·앱 자신의 작업(own)·폭주(flood)

모두 통과(switch 11, own 8, flood 7). `switch-empty.png` 는 마지막 폴더를 해제한 뒤 빈 상태(제목 `Open Recent Project`, 안내 `Choose one of the options below to use the Project Panel`, `Open Project` 버튼)를 보여 준다.

- switch: 감시 중인 폴더의 윗 폴더(`h1`) 이름 바꾸기가 `Access … denied` 로 막히고(감시 핸들), 다른 폴더로 전환하면 `watch-stop … via=activate`+`watch-start` 후 풀린다. 활성이 아닌 폴더의 변경은 1.5초 동안 `watch-applied` 0. 다시 활성화하면 그동안의 `inactive.txt` 가 트리에, 바뀐 `a.txt` 를 탭이 다시 읽는다. 마지막 폴더를 해제하면 `watch-stop via=remove` 이고 새 감시가 없다.
- own: 앱 자신의 이름 바꾸기가 일으킨 이벤트는 모두 `own=3 external=0`, 탭을 다시 넣지 않고(`tab-reload` 0) 선택·탭이 `renamed.txt` 하나. 그 직후의 다른 경로 바깥 변경은 `external=3` 으로 반영.
  - `own-deferred.png`: 인라인 입력 중(`typing` 입력칸이 `<new file>` 자리에 있음) 바깥 변경은 `tree=deferred` 이고 입력칸이 그대로, 트리 뒤쪽에 `after-own.txt`·`README.md`·`renamed.txt` 가 보인다. 입력을 끝내면 `watch-refresh via=deferred` 로 새 행 `during-edit.txt` 가 나타난다.

## 8. 정션 안 변경(한계)

- 판정 1개(통과): 루트 안 다른 파일을 만들면 전체를 다시 읽어 정션 안 파일도 함께 보인다(`poke.txt`·`via-target.txt`·`via-link.txt`).
- 관찰 2개(`observations`): 정션 대상 경로로, 또는 정션 경로로 파일을 만들어도 3초 안에 감시 이벤트가 오지 않아 반영되지 않았다(`app_ms=null`).
- 이것은 SPEC R-24 "활성 폴더 안에서 바깥 프로그램이 만들면 트리에 반영된다"의 예외다. EVIDENCE·PROGRESS 가 "알려진 한계"로 적었다. 이번에는 통과/실패가 아니라 한계로 둔다(SPEC 에 정션 언급이 없다). → §11 요청.

## 9. D-18 범위 밖 (판정 대상 아님)

SPEC R-24 와 D-18 이 이후 버전으로 미룬 것: 수정한 버퍼의 충돌 표시(E-086 뒷부분, 탭 점 Warning 색), 지워진 파일 탭의 취소선(E-087), 저장 때 확인창(E-084·E-085). 이번 증거에서 따로 판정하지 않았다.
- 탭이 보기 전용이라(D-18) 모든 버퍼가 깨끗하고, 그래서 E-086 앞부분("수정하지 않은 버퍼는 자동으로 다시 읽는다")만 판정 대상이다(§5).
- 지워진 파일의 탭은 취소선 없이 그대로 남고 내용도 그대로다. 이 동작은 판정 사항이 아니라 D-18 범위 밖의 현 상태로만 적는다.

# v0.2 Phase 5 리뷰 1회차(D-046) 수정 증거

생성: 2026-11-02. 앞선 증거(`phase5/`, `optimized*/`)는 덮어쓰지 않았다.

## 재현 방법

- 사례 스크립트: `tools/verify-v02-phase5-d046.ps1`(Phase 5 스크립트와 같은 안전 규칙·도우미).
  - 시험 폴더 `target\phase5-folders\run-<id>`(표지 `.wg-p5-run`) 안에서만 바깥 변경·정션을 만들고, 끝에 표지가 같을 때만 지웠다.
- 고치기 전 실행 파일: stage 해 둔 Phase 5 판(리뷰 전 그대로)에 **시험 훅 `--dev-slow-io` 만 더해** 빌드했다.
  - 훅은 ⑤ 재현에만 쓴다. 경로에 주어진 조각이 든 폴더 존재 확인·탭 파일 다시 읽기를 주어진 ms 만큼 늦춘다.
  - 이 PC 에서는 응답 없는 UNC 경로가 즉시 실패해(측정 0~7ms) 느린 저장 장치를 실제로 만들 수 없었다.
  - 훅 차이는 `src/dev.rs`(플래그), `folders.rs` `refresh_missing`, `watch.rs` 다시 읽기 앞 각 한 줄이다. 고친 판에도 같은 훅이 그대로 있다.
- 결과
  - `before/`: 판정 23 중 실패 18. 통과 5건은 사례 준비가 됐는지 보는 전제 판정이다.
  - `after/`: 판정 23, 실패 0.
  - 두 실행 모두 사용자 파일 해시가 같았고, 시험 폴더는 남지 않았다.

## 고친 내용

- ① `fsops/watch.rs` `SelfOps::record_rename`·`take_rename`
  - 앱의 `rename`·`paste-move`(성공)는 `log_fs` 가 (옛 경로, 새 경로) 짝으로 남긴다.
  - 감시 묶음을 받을 때 같은 짝은 한 번 쓰고 지우며, 적용하지 않는다(`own_renames`).
  - 그 밖의 앱 자신 이벤트는 집계만 한다. 트리·탭은 디스크 내용으로 다시 확인할 뿐이라 결과가 같고, 직후의 바깥 변경도 놓치지 않는다.
- ② `ui/watch.rs`
  - 인라인 입력 중에는 묶음을 통째로(받을 때 가려 둔 바깥 이름 바꾸기 짝 포함) `deferred_batches` 에 보관한다.
  - 입력이 끝나면 받은 차례대로 반영한다: 이름 바꾸기 따라가기 → 트리 다시 읽기 → 탭 다시 읽기.
- ③ `fsops/ident.rs` `dir_id`(볼륨 일련번호 + 파일 번호, GetFileInformationByHandle)
  - 감시를 등록할 때 루트 정체를 남긴다.
  - 루트 자신의 Remove·RenameFrom 이나 감시 오류(`Batch::root_replaced`)를 받으면 존재 확인 결과를 보고, 루트가 있으면 다시 등록한다.
  - 1초 확인에서 루트 정체가 달라져도 다시 등록한다. 다시 등록한 뒤 트리·탭을 모두 다시 읽는다.
- ④ `ui/watch_io.rs` `sync_tab_real`
  - 열린 탭 목록이 바뀌면 백그라운드에서 탭·루트의 실제 경로를 구한다.
  - 루트 실제 트리 밖이면 그 부모를 한 단계만 감시한다(`watch-extra`). 같은 받는 쪽을 쓰며, 루트 감시와 함께 버린다.
  - 이벤트가 실제 경로로 와도 탭을 찾도록 탭→실제 경로 표를 둔다. 정션 안 트리 반영은 알려진 한계로 남긴다(D-046 ④).
- ⑤ `ui/watch_io.rs`
  - 등록 폴더 존재·루트 정체 확인과 탭 파일 읽기·UTF-8 바꾸기·해시를 백그라운드에서 한다.
  - 결과는 폴더 목록이 그대로일 때, 같은 탭(편집기 엔티티·경로)이 아직 있을 때만 UI 스레드에 쓴다.
  - 내용 비교는 탭에 넣은 내용의 해시(`Tab::hash`)로 한다. 같으면 글을 넘기지 않는다.
  - 일은 하나씩만 돌고, 도는 동안 온 요청은 모았다가 한 번 더 돈다.
  - 폴더 활성화는 그 폴더만 바로 확인하고 나머지는 백그라운드로 넘긴다. 창 활성 때 확인도 백그라운드로 옮겼다.

## 남은 것

- 시작 때(창을 띄우기 전) 등록 폴더 존재 확인은 Phase 3 그대로 한 번 동기로 한다(`FolderList::load`).
- 트리 다시 읽기(폴더 목록 읽기)는 Phase 4 그대로 UI 스레드에서 한다. 리뷰 지적 범위 밖이다.
- 정션 안 트리 반영, 감시 중인 폴더(그리고 루트 밖 열린 파일의 부모)의 윗 폴더 이름 바꾸기 막힘은 알려진 한계로 둔다.

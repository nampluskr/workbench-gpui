# workbench-gpui

Zed의 레이아웃과 사용감을 재현하는 Windows용 편집기 베이스 앱입니다. [gpui-kit](https://gpui-kit.com/)(gpui + gpui-component) 위에서 만듭니다.

여러 작업 폴더를 등록해 트리로 보고, 파일을 탭으로 엽니다. Windows 앱을 만들 때마다 같은 껍데기를 처음부터 다시 만들지 않도록, 공통 베이스를 한 벌로 두는 것이 목표입니다. 왜 만드는지와 지킬 원칙은 [INTENT.md](INTENT.md)에 있습니다.

> Zed 앱의 포크가 아니라 재구현입니다. Zed 앱 코드(GPL-3.0)는 복사하지 않고, 동작은 명세로 정리한 뒤 그 명세와 대조해 맞춥니다. 의존하는 것은 gpui·gpui-kit(Apache-2.0)뿐입니다. 이 프로젝트는 Zed Industries와 관계가 없습니다.

## 현재 상태

[v0.2](specs/v0.2/)까지 끝났습니다. 아직 파일 편집과 저장은 되지 않습니다. 탭은 보기 전용입니다.

| 버전 | 범위 | 결과 |
| --- | --- | --- |
| [v0.1](specs/v0.1/) | 커스텀 타이틀 바·창 버튼, 편집기 PoC(한글 IME·큰 파일·인코딩), 레이아웃 뼈대(사이드바·Dock·Pane·탭 바·상태 표시줄) | 레이아웃 치수가 Zed 명세와 ±1px 안. 편집기에서 직접 구현할 12건을 정함 |
| [v0.2](specs/v0.2/) | 키맵 로더·액션, 툴팁·☰ 메뉴, 폴더 등록·사이드바, 프로젝트 패널 트리·파일 작업, 최소 탭, 디스크 감시 | 요구 R-1~R-28 통과. 판정 불가 1건(휴지통 안 확인) |

남은 일과 알려진 한계는 각 버전 PROGRESS의 "버전 종료" 절에 있습니다. [v0.2 PROGRESS](specs/v0.2/PROGRESS.md)를 보세요.

## 지금 되는 것

- **창:** Zed 모양의 커스텀 타이틀 바와 창 버튼. 스냅 레이아웃, 더블클릭 최대화, 끌기 이동, 테두리 리사이즈가 됩니다.
- **폴더:** 여러 폴더를 사이드바에 등록하고, 활성화·해제·순서 바꾸기를 합니다. 등록을 해제해도 디스크의 폴더는 그대로입니다. 폴더 목록·순서·활성 폴더·사이드바 폭은 `state.json`에 저장되고 다음 실행 때 복원됩니다.
- **프로젝트 패널:**
  - 활성 폴더를 트리로 봅니다.
  - 새 파일·새 폴더·이름 바꾸기를 트리 안 입력칸에서 합니다.
  - 잘라내기·복사·붙여넣기·복제·경로 복사를 합니다.
  - 휴지통으로 보내기와 영구 삭제는 Windows 확인창을 거칩니다.
- **탭:** 트리에서 한 번 클릭하면 임시 탭(기울임 제목)으로 열고, 더블클릭하면 일반 탭이 됩니다. 탭은 폴더마다 따로 있습니다.
- **디스크 감시:** 바깥 프로그램이 파일을 만들거나 지우거나 바꾸면 트리와 열린 탭에 반영합니다.
- **키맵:** 내장 키맵 위에 사용자 `keymap.json`을 얹습니다. 주석과 끝 쉼표를 허용합니다. 저장하면 바로 다시 읽고, 메뉴·툴팁의 단축키 표시도 바뀝니다.

### 주요 단축키

| 키 | 동작 |
| --- | --- |
| `Ctrl+K` `Ctrl+O` | 폴더 추가 |
| `Ctrl+Alt+J` | 사이드바 열기·닫기 |
| `Ctrl+Alt+;` | 사이드바 포커스 |
| `Ctrl+B` | 왼쪽 Dock(프로젝트 패널) 열기·닫기 |
| `Ctrl+Shift+E` | 프로젝트 패널 포커스 |
| `F10` | ☰ 앱 메뉴 |
| `Ctrl+Shift+W` | 창 닫기 |
| `Ctrl+Q` | 끝내기 |

### 설정 파일

`%APPDATA%\workbench-gpui\` 아래에 둡니다.

- `keymap.json`: 사용자 키맵입니다. 값을 `null`로 두면 내장 바인딩을 해제합니다.
- `state.json`: 등록 폴더 목록과 창 상태입니다. 앱이 씁니다.

## 빌드와 실행

Windows 전용입니다.

**준비물**
- Rust(edition 2024)
- Visual Studio Build Tools(MSVC)
- Windows SDK
- PowerShell 7: 매니페스트 병합 스크립트에 필요합니다.

개발한 환경은 rustc 1.99.1, Build Tools 2022, Windows SDK 10.0.26100.0입니다. 최소 Rust 버전은 아직 정하지 않았습니다.

```powershell
cargo build
pwsh -NoProfile -File tools/apply-manifest.ps1   # 빌드할 때마다 다시 실행
cargo run
```

**`apply-manifest.ps1`이 필요한 이유**
- gpui가 exe에 넣는 매니페스트에는 `longPathAware`가 없습니다.
- 이 스크립트가 빌드한 exe의 매니페스트에 `longPathAware`를 병합합니다.
- `cargo build`를 하면 병합이 사라지므로 빌드할 때마다 다시 실행해야 합니다.
- 긴 경로(260자 초과)를 실제로 쓰려면 Windows 설정 `LongPathsEnabled`도 켜져 있어야 합니다.

## 검증

`tools/verify-*.ps1`이 앱을 띄우고 실제 키·마우스 입력으로 조작한 뒤, 스크린샷과 측정값을 남깁니다. 결과와 판정 보고서는 `specs/<버전>/verify/` 아래에 있습니다.

**스크립트를 돌릴 때 알아 둘 것**
- **화면 잠금:** 입력을 보내야 해서 화면이 잠겨 있으면 멈춥니다.
- **관리자 창:** 관리자 권한 창이 맨 앞에 있어도 멈춥니다.
- **실행 중인 앱:** 같은 앱이 이미 실행 중이면 사용자 파일을 바꾸기 전에 중단합니다.
- **사용자 파일·클립보드:** 실행 전에 백업하고 끝나면 복원합니다.
- **시험 폴더:** 스크립트가 직접 만든 시험 폴더만 정리합니다.

```powershell
pwsh -NoProfile -File tools/verify-v02-phase4.ps1
```

## 저장소 구성

```
src/
  ui/        화면(타이틀 바·레이아웃·사이드바·프로젝트 패널·탭·메뉴·툴팁·감시)
  keymap/    내장 키맵, keymap.json 읽기, 단축키 표시 형식
  fsops/     파일 작업·트리 만들기·이름 검증·디스크 감시(gpui 무관)
  state/     state.json 읽기·쓰기, 경로 정규화
  dev.rs     디버그 빌드 전용 시험 플래그
tools/       빌드 보조·검증 스크립트
specs/       버전별 문서(INTENT·DECISIONS·SPEC·PLAN·PROGRESS)와 검증 증거
docs/        멀티 에이전트 구성과 결정 기록
```

## 개발 방식

**버전 문서**
- 버전마다 `specs/<버전>/`에 문서를 둡니다.
  - INTENT: 목적과 범위
  - DECISIONS: 설계 결정
  - SPEC: 요구(R-n)와 판정 방법
  - PLAN: Phase별 계획
  - PROGRESS: 한 일과 검증 기록
- 지난 버전 폴더는 고치지 않습니다.

**진행 순서**
- Phase마다 구현 → 적대적 코드 리뷰 → 명세 대조 검증 → PROGRESS 기록 → 커밋 순서로 진행합니다.
- 해결하지 못한 실패가 있으면 다음 Phase로 넘어가지 않습니다.

**에이전트와 결정 기록**
- 구현·리뷰·검증은 여러 AI 에이전트가 나눠 맡습니다([docs/HERDR-SETUP.md](docs/HERDR-SETUP.md)).
- 진행 중에 내린 결정과 근거는 [docs/HERDR-DECISIONS.md](docs/HERDR-DECISIONS.md)에 있습니다.

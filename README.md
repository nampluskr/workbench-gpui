# workbench-gpui

Zed의 레이아웃과 사용감을 재현하는 Windows용 편집기 베이스 앱입니다. [gpui-kit](https://gpui-kit.com/)(gpui + gpui-component) 위에서 만듭니다.

여러 작업 폴더를 등록해 트리로 보고, 파일을 탭으로 엽니다. Windows 앱을 만들 때마다 같은 껍데기를 처음부터 다시 만들지 않도록, 공통 베이스를 한 벌로 두는 것이 목표입니다. 왜 만드는지와 지킬 원칙은 [INTENT.md](INTENT.md)에 있습니다.

> Zed 앱의 포크가 아니라 재구현입니다. Zed 앱 코드(GPL-3.0)는 복사하지 않고, 동작은 명세로 정리한 뒤 그 명세와 대조해 맞춥니다. 의존하는 것은 gpui·gpui-kit(Apache-2.0)뿐입니다. 이 프로젝트는 Zed Industries와 관계가 없습니다.

## 현재 상태

[v0.4](specs/v0.4/)의 Phase 0~4 구현·리뷰를 마쳤으며, 사용자 테스트와 버전 종료 판단을 기다리고 있습니다. 파일 편집·저장, 핀 탭, 분할·탭 드래그, 마크다운 미리보기를 사용할 수 있습니다.

| 버전 | 범위 | 결과 |
| --- | --- | --- |
| [v0.1](specs/v0.1/) | 커스텀 타이틀 바·창 버튼, 편집기 PoC(한글 IME·큰 파일·인코딩), 레이아웃 뼈대(사이드바·Dock·Pane·탭 바·상태 표시줄) | 레이아웃 치수가 Zed 명세와 ±1px 안. 편집기에서 직접 구현할 12건을 정함 |
| [v0.2](specs/v0.2/) | 키맵 로더·액션, 툴팁·☰ 메뉴, 폴더 등록·사이드바, 프로젝트 패널 트리·파일 작업, 최소 탭, 디스크 감시 | 요구 R-1~R-28 통과. 판정 불가 1건(휴지통 안 확인) |

## 지금 되는 것

- **창:** Zed 모양의 커스텀 타이틀 바와 창 버튼. 스냅 레이아웃, 더블클릭 최대화, 끌기 이동, 테두리 리사이즈가 됩니다.
- **폴더:** 여러 폴더를 사이드바에 등록하고, 활성화·해제·순서 바꾸기를 합니다. 등록을 해제해도 디스크의 폴더는 그대로입니다. 폴더 목록·순서·활성 폴더·사이드바 폭은 `state.json`에 저장되고 다음 실행 때 복원됩니다.
- **프로젝트 패널:**
  - 활성 폴더를 트리로 봅니다.
  - 새 파일·새 폴더·이름 바꾸기를 트리 안 입력칸에서 합니다.
  - 잘라내기·복사·붙여넣기·복제·경로 복사를 합니다.
  - 휴지통으로 보내기와 영구 삭제는 Windows 확인창을 거칩니다.
- **탭·편집:** 트리에서 한 번 클릭하면 임시 탭(기울임 제목)으로 열고, 더블클릭하거나 편집하면 일반 탭이 됩니다. 편집·저장과 저장 전 닫기 확인, 핀 고정·닫기 보호를 지원합니다. 탭은 폴더마다 따로 있습니다.
- **분할:** 상하좌우 분할, 분할선 크기 조절, 활성 pane 확대·복귀를 지원합니다. 탭을 끌어 순서를 바꾸거나 다른 pane으로 옮기고, 본문 가장자리에 놓아 분할할 수 있습니다.
- **마크다운:** `.md`·`.markdown` 파일에서 툴바의 눈 모양 버튼이나 단축키로 미리보기를 엽니다. 원문 편집 내용이 미리보기에 반영됩니다.
- **디스크 감시:** 바깥 프로그램이 파일을 만들거나 지우거나 바꾸면 트리와 열린 탭에 반영합니다.
- **키맵:** 내장 키맵 위에 사용자 `keymap.json`을 얹습니다. 주석과 끝 쉼표를 허용합니다. 저장하면 바로 다시 읽고, 메뉴·툴팁의 단축키 표시도 바뀝니다.

### 주요 단축키

| 키 | 동작 |
| --- | --- |
| `Ctrl+K` `Ctrl+O` | 폴더 추가 |
| `Ctrl+Alt+J` | 사이드바 열기·닫기 |
| `Ctrl+Alt+;` | 사이드바 포커스 |
| `Ctrl+B` | 왼쪽 Dock(프로젝트 패널) 열기·닫기 |
| `Ctrl+Shift+E` | 프로젝트 패널 포커스 |
| `F10` | ☰ 앱 메뉴 |
| `Ctrl+S` | 활성 파일 저장 |
| `Ctrl+W` / `Ctrl+F4` | 활성 탭 닫기(핀 탭 보호) |
| `Ctrl+K` `Shift+Enter` | 활성 탭 핀 고정·해제 |
| `Ctrl+\` | 오른쪽 분할 |
| `Ctrl+K` `↑` / `↓` / `←` / `→` | 해당 방향으로 분할 |
| `Ctrl+K` `Ctrl+↑` / `Ctrl+↓` / `Ctrl+←` / `Ctrl+→` | 해당 방향 pane으로 이동 |
| `Shift+Escape` | 활성 pane 확대·복귀 |
| `Ctrl+Shift+V` | 마크다운 미리보기 열기·원문 복귀 |
| `Ctrl+K` `V` | 마크다운 미리보기를 오른쪽 pane에 열기 |
| `Ctrl+Shift+W` | 창 닫기 |
| `Ctrl+Q` | 끝내기 |

`Ctrl+K` 뒤의 키는 첫 키를 놓은 뒤 순서대로 누릅니다. 핀·분할·미리보기 키는 가운데 탭/편집기 영역에 포커스를 두고 사용하세요. 사용자 `keymap.json`이 있으면 위 기본 단축키와 다를 수 있습니다.

### 설정 파일

`%APPDATA%\workbench-gpui\` 아래에 둡니다.

- `keymap.json`: 사용자 키맵입니다. 값을 `null`로 두면 내장 바인딩을 해제합니다.
- `state.json`: 등록 폴더 목록과 창 상태입니다. 앱이 씁니다.

## 빌드와 실행

Windows 전용입니다.

**준비물**
- Rust(edition 2024)
- Visual Studio Build Tools(MSVC)
- Windows SDK
- PowerShell 7: 매니페스트 병합 스크립트에 필요합니다.

개발한 환경은 rustc 1.99.1, Build Tools 2022, Windows SDK 10.0.26100.0입니다. 최소 Rust 버전은 아직 정하지 않았습니다.
- v0.1·v0.2는 노트북에서 만들었습니다.
- v0.3부터는 데스크톱에서 같은 버전으로 맞춰 작업합니다(`specs/v0.3/HERDR-SETUP.md` 3.7).
- 보조 스크립트는 PowerShell 7로 씁니다. Python이 필요하면 WinPython을 전체 경로로 부릅니다.
  - 기본: `C:\winpython\WPy64-31180_cpu\python-3.11.8.amd64\python.exe`
  - GPU가 필요할 때: `C:\winpython\WPy64-31180_gpu\python-3.11.8.amd64\python.exe`

PowerShell에서 저장소 루트로 이동해 빌드하고, 매니페스트를 적용한 실행 파일을 직접 엽니다.

```powershell
cd D:\projects\workbench-gpui
$env:CARGO_TARGET_DIR = 'D:\projects\workbench-gpui\target'
cargo build
pwsh -NoProfile -File tools/apply-manifest.ps1
.\target\debug\workbench-gpui.exe
```

앱을 닫은 뒤 다시 켜기만 할 때는 마지막 줄만 실행하면 됩니다. 소스를 바꾸거나 다른 worktree를 빌드했다면 위 빌드·매니페스트 적용을 다시 하세요. worktree들이 같은 target 폴더를 사용하므로 실행 파일은 마지막에 빌드한 소스 기준입니다.

**`apply-manifest.ps1`이 필요한 이유**
- gpui가 exe에 넣는 매니페스트에는 `longPathAware`가 없습니다.
- 이 스크립트가 빌드한 exe의 매니페스트에 `longPathAware`를 병합합니다.
- `cargo build`를 하면 병합이 사라지므로 빌드할 때마다 다시 실행해야 합니다.
- 긴 경로(260자 초과)를 실제로 쓰려면 Windows 설정 `LongPathsEnabled`도 켜져 있어야 합니다.

다른 PC로 옮길 배포본(zip) 만들기와 복사본 채우기는 [docs/BUILD.md](docs/BUILD.md)를 보세요.

## 검증

### 사용자가 직접 UI 테스트하기

별도 시험 폴더에 텍스트 파일 2개와 마크다운 파일 1개를 준비하세요. 저장·디스크 변경 테스트는 이 파일들로 진행합니다.

1. **폴더·탭:** 실행 후 `Ctrl+K` `Ctrl+O`로 시험 폴더를 추가합니다. 트리의 파일을 한 번 클릭하면 임시 탭, 더블클릭하면 일반 탭이 되는지 확인합니다.
2. **편집·저장:** 텍스트를 바꾸고 수정 점이 나타나는지 확인합니다. `Ctrl+S`로 저장한 뒤 외부 편집기로 파일 내용이 같은지 확인합니다.
3. **저장 전 닫기:** 한 파일을 수정하고 그 파일의 마지막 뷰에서 `Ctrl+W`를 누릅니다. 저장·버리기·취소 질문이 뜨는지, 취소하면 편집 내용이 남는지 확인합니다. 같은 파일이 다른 pane이나 미리보기에 남아 있으면 마지막 뷰가 아니므로 질문 없이 해당 탭만 닫힐 수 있습니다.
4. **핀 탭:** `Ctrl+K` `Shift+Enter`로 핀을 고정합니다. 탭이 앞쪽으로 이동하고 `Ctrl+W`·가운데 클릭으로 닫히지 않는지 확인합니다. 같은 키나 탭 우클릭 메뉴로 핀을 해제합니다.
5. **분할·확대:** `Ctrl+\` 또는 View 메뉴로 분할합니다. 분할선을 끌어 크기를 바꾸고 `Shift+Escape`로 활성 pane을 확대·복귀합니다. 같은 파일의 두 뷰에서 편집 내용이 함께 바뀌는지도 확인합니다.
6. **탭 드래그:** 탭을 끌어 순서를 바꾸고 다른 pane으로 이동합니다. 본문 가장자리에 놓으면 새 pane이 생깁니다. `Ctrl`을 누른 채 다른 pane으로 끌면 원본 뷰를 남겨 복제합니다.
7. **마크다운:** `.md` 파일을 열어 눈 모양 버튼이나 `Ctrl+Shift+V`로 미리보기를 엽니다. `Ctrl+K` `V`로 옆 미리보기도 열고, 원문 변경이 반영되는지 확인합니다. 미리보기에서 `Ctrl+Shift+V`를 누르면 원문으로 돌아갑니다.
8. **디스크 감시:** 앱에서 저장을 마친 파일을 외부 편집기로 바꾸면 열린 내용이 갱신되는지 확인합니다. 앱 안에서 수정한 상태로 외부 파일을 바꾸면 앱의 편집 내용이 유지되고 충돌 상태가 표시되는지 확인합니다.

현재 알려진 차이: 마크다운 h1·h2 아래 선/여백(L-105)과 링크 밑줄 불투명도(L-108)는 컴포넌트 한계로 남아 있습니다. 프로젝트 패널의 파일을 끌어서 여는 기능과 탭·분할 배치의 재실행 복원은 이번 버전 범위 밖입니다. 그 밖의 사용자 확인 항목은 [PROGRESS](specs/v0.4/PROGRESS.md)에 있습니다.

문제를 발견하면 앱을 실행한 커밋, 재현 순서, 기대 동작과 실제 동작, 창 크기·화면 배율, 필요하면 스크린샷을 함께 남겨 주세요.

UI를 띄우지 않고 단위 테스트와 정적 검사를 실행합니다. 저장소 루트에서 실행하세요.

```powershell
$env:CARGO_TARGET_DIR = 'D:\projects\workbench-gpui\target'
cargo test

```

### 자동 UI 검증(개발용)

`tools/verify-*.ps1`이 앱을 띄우고 실제 키·마우스 입력으로 조작한 뒤, 스크린샷과 측정값을 남깁니다. 결과와 판정 보고서는 `specs/<버전>/verify/` 아래에 있습니다.

**스크립트를 돌릴 때 알아 둘 것**
- **화면 잠금:** 입력을 보내야 해서 화면이 잠겨 있으면 멈춥니다.
- **관리자 창:** 관리자 권한 창이 맨 앞에 있어도 멈춥니다.
- **실행 중인 앱:** 같은 앱이 이미 실행 중이면 사용자 파일을 바꾸기 전에 중단합니다.
- **사용자 파일·클립보드:** 실행 전에 백업하고 끝나면 복원합니다.
- **시험 폴더:** 스크립트가 직접 만든 시험 폴더만 정리합니다.

기본 레이아웃은 아래 명령으로 자동 대조할 수 있습니다. 먼저 앱을 닫고 빌드·매니페스트 적용을 마치세요. 주 모니터 100% 배율 기준이며, 실행 중에는 다른 창으로 가리거나 키·마우스를 조작하지 마세요. 결과는 임시 폴더에 저장됩니다.

```powershell
pwsh -NoProfile -File tools/measure/check-layout.ps1 -Exe D:\projects\workbench-gpui\target\debug\workbench-gpui.exe
```

v0.2 회귀 스크립트는 옛 동작을 기대하므로 v0.4의 의도한 변경도 실패로 표시할 수 있습니다. 버전별 사본과 결과 해석은 [Phase 4 실측 보고서](specs/v0.4/verify/reviews/measure-phase4.md)를 따릅니다. `verify-v02-*.ps1`을 직접 실행할 때는 지난 버전 결과를 덮어쓰지 않도록 `-OutDir specs\v0.4\verify\<새 결과 폴더>`와 절대 경로의 `-Exe`를 명시하세요.

```

  keymap/    내장 키맵, keymap.json 읽기, 단축키 표시 형식
  fsops/     파일 작업·트리 만들기·이름 검증·디스크 감시(gpui 무관)
  state/     state.json 읽기·쓰기, 경로 정규화
  dev.rs     디버그 빌드 전용 시험 플래그
tools/       빌드 보조·검증 스크립트
specs/       버전별 문서(INTENT·DECISIONS·SPEC·PLAN·PROGRESS), 멀티 에이전트 운영(HERDR-*), 검증 증거
spec/        Zed 실측 수치 스펙(zed-metrics.toml, v0.3부터)
docs/        참고 자료(refs/: Zed 명세·리팩토링 기준 초안), v0.1·v0.2 멀티 에이전트 기록(HERDR-*)
```

## 개발 방식

**버전 문서**
- 버전마다 `specs/<버전>/`에 문서를 둡니다.
  - INTENT: 목적과 범위
  - DECISIONS: 설계 결정
  - SPEC: 요구(R-n)와 판정 방법
  - PLAN: Phase별 계획
  - PROGRESS: 한 일과 검증 기록
- 지난 버전 폴더는 고치지 않습니다.

**진행 순서**
- Phase마다 구현 → 적대적 코드 리뷰 → 명세 대조 검증 → PROGRESS 기록 → 커밋 순서로 진행합니다.
- 해결하지 못한 실패가 있으면 다음 Phase로 넘어가지 않습니다.

**에이전트와 결정 기록**
